## 2. 本轮实际改了什么

审计发现 §10「错误恢复」五条里，**四条已存在**（手动录入、临时识别副本、去重预览、单门标出不完整），
只有**解码失败那一条**不达标。因此本轮**只补这一条**，其余四条加注说明而不改行为。

### 2.1 解码失败的消息：给出文件名与支持格式

原文案是"无法读取这张图片。请确认文件没有被移动或删除，也可以重新选择 PNG 或 JPG。"——
**没有文件名**，用户面对一个文件夹里三五张图时不知道是哪张出问题。

现在：`无法读取「我的课表.png」。请确认文件没有被移动或删除，或换一张图（支持 PNG、JPG、JPEG）。`

**只给文件名，不给目录**（`_fileName` 取 basename，兼容 `\` 与 `/`）：§10 一边要求显示文件名，
一边要求"图片原件不写入数据库、不上传"。把 `F:\downloads\私密目录\...` 摆在界面上没有必要，
而且截图或录屏时会跟着外泄用户的目录结构。**有专门一条用例钉住父目录名不出现。**

### 2.2 原始异常一律吞掉，换成人话（§10 最后一条退出条件）

原来的兜底分支 `catch (_)` 给的是"课表识别失败，图片仍已保留"——**这句是错的**：
它把"读不出文件"说成了"识别失败"，把用户引向"重试识别"而不是"检查这张图"。

现在兜底分支也走"无法读取「文件名」…"那一套，并且**吞掉原始异常**。
底层读取失败会以各种运行时异常形式冒出来（`PathAccessException`、`FileSystemException`、
平台通道错误……），它们的类型名与 `OS Error 5` 之类的文本对用户毫无意义。

### 2.3 失败处**就地**给出「更换图片」

新增 `timetable-change-image` 按钮，只在**与图片有关**的失败（`decodeFailed` / `imageTooLarge`）时出现。

- 为什么要就地：§10 要求"图片读取失败时能换图"。用户读完原因后，动作必须在**同一处**，
  否则还要回头找上方那个通用选择按钮；
- 为什么只对这两种显示：换一张图**解决不了**"本机没装中文 OCR"或"设备不支持本地识别"，
  给了反而把用户引到错的方向（有用例钉住 `languageUnavailable` 时该按钮**不存在**）。
