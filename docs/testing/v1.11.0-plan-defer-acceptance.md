## 4. 已知风险 / 需要下一轮先看的点

- `PendingPlanPreviewService` 仍直接使用 `DriftRecurringExecutionRepository` 的预览方法；
  通用仓储 `DriftPendingPlanPreviewRepository` 已实现但未替换调用方（两个实现共享同一组表，
  目前行为一致）。
- 旧 `PendingMoveDrafts._adjustment` 字段已不再被延后路径使用；在确认旧路由符号全部移除前
  暂不删除，避免误伤其他调用方。
- `ScheduleProposalCodec` 显式拒绝 `ScheduleRuleOverride`（特殊日恢复提案）。
  调整预览不会产生该字段；若将来需要持久化特殊日提案，必须先补 codec。
- 撤销时未开始 occurrence 的 `execution_block_links` 已**新增**指向恢复版本的行，旧行保留；
  已开始的执行仍整体阻断。历史行不改写是刻意选择（主键含 `plan_version_id`）。
- `confirmAdjustment` 在应用事务前重新校验硬约束与兑现，但**事务内**没有再读一次
  计划事实；现行 CAS + 令牌 + 基线版本已覆盖竞态，未覆盖"确认与提交之间块被移动"的极小窗口。
- 本机 Dart `Link.create` 报 1314，`flutter build windows --release` 需要先按第 1 节的
  PowerShell 片段预建插件符号链接；这是环境差异，不是产品缺陷。
