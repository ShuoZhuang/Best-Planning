## 4. 已知风险 / 需要下一轮先看的点

- `PendingPlanPreviewService` 仍直接使用 `DriftRecurringExecutionRepository` 的预览方法；
  通用仓储 `DriftPendingPlanPreviewRepository` 已实现但未替换调用方（两个实现共享同一组表，
  目前行为一致）。
- `PendingMoveDrafts._adjustment` 仍在生产 router 中使用；在 Task 9 接线前**不能删除**，
  否则延后入口会彻底失效。
- `ScheduleProposalCodec` 显式拒绝 `ScheduleRuleOverride`（特殊日恢复提案）。
  调整预览不会产生该字段；若将来需要持久化特殊日提案，必须先补 codec。
- 撤销**不改写 `execution_block_links` 的历史行**（其主键含 `plan_version_id`）：
  未开始的 occurrence/fragment 已重定向到恢复版本，link 行按版本保留。Task 11 的
  "恢复 links"仍是 PARTIAL，需要按"新增恢复版本 link + 保留旧行"的方案补齐。
- `confirmAdjustment` 在应用事务前重新校验硬约束与兑现，但**事务内**没有再读一次
  计划事实；Task 10 的"事务内校验"仍需在仓储里补一层（当前 CAS + 令牌 + 基线版本
  已覆盖竞态，未覆盖"确认与提交之间块被移动"的极小窗口）。
- `flutter analyze` 在本机需要开发者模式；不得把 `dart analyze` 的结果写成 `flutter analyze`
  的等效证据。
