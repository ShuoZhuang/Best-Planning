## 2. 共享场景夹具（Task 1 Step 2）

`test/fixtures/core_workflow_repair_scenarios.dart` 只放**纯数据构造器**，不放断言、不放 `test()`。
时刻一律经 `TimeZoneDatabase` 从**本地墙上时间**换算，不写 UTC 字面量——否则 Asia/Shanghai 的
`+08:00` 会被硬编码进测试，柏林夏令时那几条就分不出"本地钟点"与"经过时长"（规范 §4.2、§11.2）。

| 场景 | 夹具方法 | 关键值 |
| --- | --- | --- |
| 上海午餐 | `shanghaiLunch()` | UTC `04:00–05:00` ⇔ 本地分钟 `720–780` ⇔ `12:00–13:00` |
| 跨午夜 | `shanghaiCrossMidnight()` | 两段：`23:30–1440` 与 `0–30`，接缝处 UTC 相等 |
| 柏林 DST | `berlinSpringForward()` / `berlinBeforeSpringForward()` | 同为本地 `03:00`，UTC 相差 **23 小时**（本地时长 23 小时的那一天） |
| 通知五类 | `notificationCategories()` | 5 条 `planner.*`（taskStart / calendarStart / deadline / conflict / recurringGoal）+ 1 条外部通知 |
| 延后目标被占 | `deferredBlockWithOccupiedTarget()` | 未锁定块 `15:10–15:25`，固定日程 `15:40–16:10` 占住下界，期望落点 `16:10` |
| orphan gap | `orphanGapBetweenFixedEvents()` | 固定日程 `10:00–10:40` 与 `11:00–11:40`，中间 **20 分钟**；最小合法片段 **30 分钟** |
| 同名不同课程 | `sameNamedDifferentCourses()` | 两门「高等数学(上)」分属不同 `logicalCourseId` |

夹具的形状由 `test/fixtures/core_workflow_repair_scenarios_test.dart` 守着（8 条）。它**刻意不测
产品行为**：上海卡片的位置属于 Task 2，延后落在哪个块属于 Task 12，orphan 是否被判成 orphan 属于
Task 13。它只钉夹具自己的事实——每个场景都构得出来、且描述的形状（"目标点确实被占"、
"20 分钟确实放不下"）成立。夹具描述错了，后面每个任务都会跟着错。
