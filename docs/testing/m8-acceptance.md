## 2. 本轮实际改了什么

### 2.1 设置首页按 §12 的四组分分组

此前是一个**九项平铺的列表**，用户要在"外观与材质""学期与节次模板""导出与备份"之间自己找。
现在按 §12 原文的四组分区：**规划与时间 → 外观与交互 → 通知与隐私 → 数据与帮助**。

`SettingsGroup` 枚举的**声明顺序就是渲染顺序**，调整顺序只改一处；
**空分组整组不渲染**（未装配的服务本来就不在列表里，留一个空标题只会让人以为"还没加载出来"）。

### 2.2 每个入口展示当前关键值

§12 举的例子就是"默认专注 50 分钟"或"信任自动调整：关闭"。此前副标题是**静态说明**，
不反映任何状态——于是想确认"自动调整到底开没开"必须点进去一项项翻，
而设置页的意义恰恰是**不用进去就能看到现状**。

新增 `SettingsValueReader`（一个只读回调），由组合根从**已有服务**读值：
规划规则读 `resolveForDate(...).rules.defaultFocusMinutes`、外观读 `AppearanceService.mode`、
窗口读 `WindowBehaviorService.load()`、应用锁读 `isEnabled()`。

**为什么"默认专注"要走 `resolveForDate` 而不是直接读用户规则**：用户规则是一层**补丁**
（`PlanningRulesPatch.defaultFocusMinutes` 可空），真实的分钟数由
"默认值 ← 常见补丁 ← 工作日/周末补丁 ← 当日覆盖"逐层应用得出。直接读补丁会在用户没改过时
拿到 `null`，于是入口上什么都不显示——而用户想问的恰恰是"现在到底是多少"。

**读失败不崩**（有用例钉住）：读不出当前值只是少一行提示，不该让整个设置页打不开。

### 2.3 修掉一个真缺陷：未保存的修改会被**静默丢弃**

规格 §1.3 之外，核实第 4 条时发现：**`lib/` 里一处 `PopScope` 都没有**。
`planning_rules_page.dart` 的 20 多个输入框只在点「保存设置」时落库，
**返回、点侧边导航、关窗口都会静默丢掉刚才的编辑**——§12 把"静默丢弃"单独列出来，
正是因为这类丢失**没有任何反馈**：用户以为改好了，下次进来发现还是老值。

修法：`PopScope(canPop: !_hasUnsavedChanges)` + 确认对话框（默认选"继续编辑"）。

**"有没有改过"的判据是载入后的快照比较，不是一个 `_dirty` 布尔。**
因为 20 多个输入框在 `_load()` 里被程序填初值，而 `TextEditingController` 分不清
"程序填的"与"用户敲的"——只看"变过没有"会把载入本身当成一次编辑，
于是**每次返回都弹确认框**，那比不提示更烦人。有专门一条用例钉住"没改过就不拦"。

#### 修的过程中踩到一个很隐蔽的坑（记下来）

第一版加上 `PopScope` 之后，**`didPop` 仍然是 `true`、确认框根本不出现**，而
`_hasUnsavedChanges` 算得**完全正确**（加了临时 `print` 才看到：`didPop=true dirty=true`）。

原因：**`PopScope` 的 `canPop` 是构建时算出来的一个值，而用户打字只改
`TextEditingController` 的文本、不会重建这一页**。框架手里一直是"载入那一刻的
`canPop = true`"。

修法是给每个控制器加监听触发重建（`_onFieldChanged` → `setState`）。

**这个坑值得单独记住**：`canPop` 是**快照语义**，不是**实时查询**。
凡是"根据可变的内部状态决定要不要拦返回"的地方，都必须保证那个状态变化会触发重建。

另外**保存成功后要重新拍快照**，否则保存完再返回仍会弹"还有未保存的修改"——
那时根本没有未保存的东西，用户只能莫名其妙点一次"放弃修改"。

### 2.4 分组带来的一个真实副作用（如实记录）

分组加了四个组标题与间距，实测把靠后的入口整体推下去了：
默认 **800×600** 窗口下「学习偏好」从"直接点得到"变成"必须滚动"
（`preferences_route_test` 因此红，报的是 tap 落在 y=626 的视口外）。

**真实窗口是 1280×720**，但小窗口本来就该能用，而分组的本意是**更好找**，
不该顺手把别的入口推下去。因此：

1. 当前值放到**右侧**（与副标题并排）而不是塞成副标题的第二行；
2. 组间距从 24/8 收紧到 14/6。

收紧后 800×600 下四个入口都直接可点，全部 `test/app/` 用例通过。
