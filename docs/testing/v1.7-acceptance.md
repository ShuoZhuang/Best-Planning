## 8. 复现方式

本项目的 Flutter 工具链有一处环境陷阱，先记下来（不照做会得到与项目无关的误导性报错）：

```powershell
# 环境前提：TEMP/TMP 指向工作区内，SDK 加进 PATH（见 README §环境前提）
cd G:\best-planing\.worktrees\native-implementation
& G:\best-planing\.tooling\fx.ps1 test          # 全套
& G:\best-planing\.tooling\fx.ps1 analyze --no-pub
```

> **为什么用 `fx.ps1` 而不是 `flutter.bat`**：`flutter.bat` 会从 `bin/internal/shared.bat`
> 里再调一次 PowerShell 去构建工具快照，在受限会话中那一步**永不返回**（实测挂起 12 分钟以上）。
> `fx.ps1` 用 SDK 自带的 `dart.exe` 直接执行缓存的 `flutter_tools.snapshot`，
> 设好 `FLUTTER_ROOT`／`TEMP`／`PUB_CACHE` 等变量，同一条命令在 0.5 秒内返回。
> 两者跑的是**同一个工具快照**，语义一致。

### 8.1 Windows Release 构建：符号链接限制与本机绕法

`flutter build windows` 会为每个含原生代码的插件在
`windows/flutter/ephemeral/.plugin_symlinks/` 下建**符号链接**。本会话的进程令牌拿不到
`SeCreateSymbolicLinkPrivilege`，flutter_tools 因此报
`ERROR_PRIVILEGE_NOT_HELD`（1314）并翻译成
"Building with plugins requires symlink support. Please enable Developer Mode"。

> **那条提示在本机是误导的**：`HKLM\...\AppModelUnlock\AllowDevelopmentWithoutDevLicense`
> 已经是 `1`（Developer Mode 已开），当前进程也是管理员，单独在别处新建符号链接同样成功。
> 真正的原因是受限会话的令牌权限，不是系统设置——所以**不要**为了这条报错去改系统设置。

绕法是改用**目录联接**（junction）：它是 NTFS 重解析点，创建它**不需要**那个特权，对构建而言
与符号链接等价（CMake 只是把 `${plugin}/windows` 当普通目录读取）。一条命令：

```powershell
& G:\best-planing\.tooling\prepare-windows-build.ps1     # 按 .flutter-plugins-dependencies 建联接
& G:\best-planing\.tooling\fx.ps1 build windows --release --no-pub
```

**实测**：加联接前 `flutter build windows --release --no-pub` 退出码 1（上面那条提示）；
加联接后连续两次成功（77.7 s / 60.8 s），产物
`build\windows\x64\runner\Release\personal_planner.exe`。

**前置条件**：先跑过一次 `fx.ps1 pub get`——`pub get` 自己会在符号链接那一步失败退出，但它已经
写好了 `.flutter-plugins-dependencies`，而那个文件是 `prepare-windows-build.ps1` 的依据。
