`ApplicationData.Current.LocalCacheFolder` 下的 `BestPlanning\Updates`；`state.json`
首次写入与覆盖写入成功；完整且哈希正确的 `.partial` 成功提升为 `.ready`；重新打开状态文件
仍能读回；旧的虚拟化目录 `LocalCache\Local` 下没有产生任何新的更新文件。

## 2. 执行方式

自检代码：`lib/platform/update/update_storage_selftest.dart`。它只在设置环境变量
`PLANNER_UPDATE_STORAGE_SELFTEST=<报告路径>` 时运行，走的是正式代码路径
（`WindowsUpdateStorage` → `UpdateStorageLayout` → `FileUpdateStateStore` →
`promoteVerifiedFile`），跑完写 JSON 报告并退出，不显示界面。

```powershell
$report = Join-Path $env:LOCALAPPDATA 'BestPlanningSetup\real-install\update-storage-selftest.json'
$pkg = Get-AppxPackage -Name 'ShuoZhuang.PersonalPlanner'
$psi = New-Object System.Diagnostics.ProcessStartInfo
$psi.FileName = Join-Path $pkg.InstallLocation 'personal_planner.exe'
$psi.UseShellExecute = $false
$psi.Environment['PLANNER_UPDATE_STORAGE_SELFTEST'] = $report
$process = [System.Diagnostics.Process]::Start($psi)
$process.WaitForExit(90000)
```

> 必须用 `UseShellExecute = $false` 直接创建进程；通过 ShellExecute/应用激活启动时，自定义
> 环境变量不会传到包进程（本轮实测：同样参数下应用正常启动但读不到环境变量）。

  旧内容不变、临时文件被清理；
- 目标位置不是文件：同样失败并保留诊断；

- 解除占用后：无需重新下载即可提升成功；
- 已打包但原生失败：抛 `UpdateStorageException`（带 HRESULT），**不回退**到
  `%LOCALAPPDATA%`；未打包：回退并标注 `unpackaged-fallback`。

## 5. 本轮发现

1. **同版本 `ForceUpdateFromAnyVersion` 不会替换已安装文件**：用 Setup 的"重新安装"覆盖
   同版本包时，`AddPackageAsync` 返回成功，但安装目录里的 `data\app.so` 仍是旧字节
   （哈希未变）。要让新字节真正生效，必须卸载后重装或抬 MSIX 第四段。本验收因此使用
   `Remove-AppxPackage` + `Add-AppxPackage`；这条限制已反馈到发布流程（重装按钮的语义需要
   后续单独修复，不属于本 P0 的落盘问题）。
2. **ShellExecute 启动的包进程拿不到自定义环境变量**：验收脚本因此显式使用
   `UseShellExecute = $false`。
3. 自检只清理文件，可能留下一个空的 `1.10.0.99` 版本目录；本轮已手动清理，不影响结论。
