## 3. 阻断原因（为什么这些项是 NOT RUN）

1. **没有执行真实构建、签名与发布**：本会话只被授权修改源码、测试与文档。`flutter build windows`、
   `msix:create`、Setup 签名、覆盖安装与回退需要用户显式授权，并需要一台可安装的实验环境。
2. **没有正式（CA 签发）代码签名证书**：仓库与 `pubspec.yaml` 指向的是自签证书
   （`CN=Shuo Zhuang, O=Personal User, C=CN`，见 `docs/release/windows-release.md` 第 2 节）。
   自签证书不能作为“正式签名验收”的证据，也不应被当作已通过。
3. **没有可演练的安装态环境**：`1.10.2` 事故机与 `1.11.0` 安装环境都不在本会话可用范围内，
   因此 1.10.2 自愈、1.11.0 → 1.11.1 升级、健康确认失败回退全部不能执行。
4. **`flutter test -d windows` 已经执行**（Developer Mode 已开启）：事故序列 integration 通过；
   但它构建的是普通调试可执行文件，**没有 MSIX 包身份**，所以受保护目录/ACL 与签名安装仍属于
   第 18～21 行的 NOT RUN。

> 以上都是**环境与授权阻断**，不是“代码已通过”。在阻断解除前，本文件任何一行都不得被改写成
> 暗示 1.11.1 已经发布或可用的结论。
