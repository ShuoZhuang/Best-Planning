# M3 规格：新建任务与领域项目闭环

> 冻结路线图 §7 的边界。路线图：`docs/superpowers/plans/2026-10-07-product-experience-master-roadmap.md`。
> **不得把 M4 及以后的内容顺手带入**（§14）。M3 **不抬版本、不单独发布**（§3）。

## 1. 用户结果（§7 原文）

用户在一个详细新建页面中看到默认值并按需修改；最常用字段**无需滚动三屏**，**保存按钮始终可见**。
领域与项目的关系在操作中自然成立，不再依赖说明文字补救。

## 2. 现状（审计结论，2026-10-07）

`lib/features/tasks/task_editor_page.dart` 目前是**一棵单列滚动树**，三个分区顺序为
「基本信息 → 分类归属 → 时间与拆分」，保存按钮是这棵树的**最后一个** `Wrap`。逐条对照 §7：

| §7 要求 | 现状 | 差距 |
| --- | --- | --- |
| 首屏固定显示：标题 | ✅ 第一项 | 无 |
| 首屏固定显示：预计时长 | ✅ | 无 |
| 首屏固定显示：领域 | ⚠️ 在第二个分区，需滚动 | **位置偏后** |
| 首屏固定显示：项目（位于领域之后，按领域过滤） | ⚠️ 同分区，逻辑已对 | **位置偏后** |
| 首屏固定显示：最早开始时间 | ⚠️ 在第三个分区 | **位置偏后** |
| 首屏固定显示：截止时间 | ⚠️ 同上 | **位置偏后** |
| 首屏固定显示：是否允许拆分 | ⚠️ 同上 | **位置偏后** |
| 「更多设置」：优先级与精力要求 | ❌ **现在就在首屏**（基本信息里） | **应当收起** |
| 「更多设置」：最短/最长片段、必须连续时长 | ⚠️ 与"是否允许拆分"同处一区 | **应拆开** |
| 「更多设置」：期望时段 | ⚠️ 同上 | **应拆开** |
| 「更多设置」：标签与备注 | ❌ 备注在首屏；**编辑器里从来没有标签控件** | **备注收起**；标签见下方说明 |
| 保存区用**固定底栏** | ❌ 保存按钮在滚动树末尾 | **缺失** |
| 底栏同时显示**缺失字段**与**关键约束摘要** | ❌ 无 | **缺失** |
| 领域切换后原项目不属于新领域 → 清空并明确说明 | 需核实 `_selectArea` | 待验证 |
| 领域页：开关改名为「计入个人生活时间」 | 需核实 | 待验证 |
| 领域页：颜色圆点改为带标签的「颜色」按钮 | 需核实 | 待验证 |
| 项目分区必须首屏可见（或「领域／项目」两个标签页） | ⚠️ 需滚动才可见 | **随首屏重排解决** |
| 不计入单任务字段：`计入个人生活时间` | 需核实编辑器里没有它 | 待验证 |

**结论**：本里程碑的工作是**信息层级与操作距离**的调整，**不改**这些字段的领域模型
（§7「已有能力」明确划界）。

## 3. 非目标

- **不动领域模型**：`PlannerTask`、`TaskDraft`、`WorkspaceService` 的字段不改。
- **不新增"周期任务"开关**（§7 周期事项边界）。
- **不改排程算法**、不改数据库结构、不改包身份。
- **不做 M4 的今日页动作**、不做 M5 的周日历。
- **不恢复独立快速收集箱**（§3 全局约束）。

## 4. 实施范围

### 4.1 首屏与「更多设置」分层

首屏（不滚动即可见）：

1. 标题
2. 预计时长
3. 领域
4. 项目（紧跟领域，按领域过滤）
5. 最早开始时间
6. 截止时间
7. 是否允许拆分

«更多设置» 展开区（默认**收起**）：

- 优先级、精力要求
- 拆分后的最短/最长片段，或必须连续时长
- 期望时段
- 备注

> **关于「标签」**：§7 原文把"标签与备注"一起列进「更多设置」。但审计后发现本工程的标签入口
> 在**任务详情页**（`TaskDetailPage(tags: ...)`，路由装配见 `router.dart` 的 `/tasks/:taskId`），
> **编辑器从来没有标签控件**。把标签搬进编辑器属于**功能搬迁**而不是信息层级调整，
> 因此本轮只收起**备注**。这一点在 `docs/testing/m3-acceptance.md` §5 有记录。

### 4.2 固定底保存栏

保存区移出滚动树，改为**固定底栏**，并同时显示：

- **缺失字段**（例如"请填写任务标题"）——用户不必滚到底才知道为什么存不了；
- **关键约束摘要**（领域、项目、最早开始、截止、拆分方式）。

**100% 与 150% Windows 缩放下都必须可见。**

### 4.3 领域与项目规则（§7）

- 新建任务时立即可选领域，**不得先保存再编辑**。
- 选择领域后才显示该领域下的项目。
- 新建项目必须选领域；**默认继承任务当前领域**，可改。
- **切换领域后，若原项目不属于新领域 → 清空项目并给出明确说明。**
- 领域/项目各用**一行短说明 + 实例**解释，不用长段落。
- 项目分区在首屏可见（随 4.1 重排达成）。

### 4.4 领域页（§7）

- 无文字开关 → 改名为**「计入个人生活时间」**。
- 颜色圆点 → 改为**带标签的「颜色」按钮**。

## 5. 强制测试

| 要求 | 测试 |
| --- | --- |
| 首屏含七个字段、「更多设置」默认收起 | Widget 测试读 widget 树：七个控件在收起状态下即可命中；优先级/精力/备注/期望时段在展开前**不可见** |
| 展开「更多设置」后可见 | 同上 + 点开后断言可见 |
| 保存按钮固定底栏 | 断言保存按钮**不在** `SingleChildScrollView` 内，而在底栏位置；并断言底栏含缺失字段与约束摘要 |
| 100% / 150% 缩放 | 用 `MediaQuery.devicePixelRatio`（或 `tester.view.devicePixelRatio`）分别渲染，断言保存按钮 `findsOneWidget` 且 hit-testable |
| 领域切换清空无效项目 | 选领域 A→项目 A1→切到领域 B（A1 不属于 B）→断言项目被清空且出现说明文字 |
| 项目按领域过滤 | 既有 `task_project_picker_test.dart` 保留并通过 |
| 不出现"先进入收集箱"路径 | 断言编辑器不显示任何"收集箱"字样/入口 |
| 领域页改名与颜色按钮 | `workspace_management_page_test.dart` 断言「计入个人生活时间」文案与「颜色」按钮 |

## 6. 退出条件（§7）

- [ ] 用默认值创建普通任务的人工计时 **< 60 秒**，实际用时写入人工验收记录。
- [ ] 领域、项目、最早开始、截止时间、拆分方式**无需展开「更多设置」**。
- [ ] 保存按钮在 **100% 和 150%** Windows 缩放下始终可见。
- [ ] 任务计划块绝不早于最早开始时间（既有测试守着，不回归）。
- [ ] 连续任务不会被拆分；可拆分任务遵守最短/最长片段（既有测试守着）。
- [ ] 领域切换不会保存无效项目关系。
- [ ] 不出现"先进入收集箱再详细设置"的路径。
- [ ] `flutter analyze` 0 问题、`dart format` 0 改动、全量 `flutter test` 全绿。
- [ ] M3 章节写入 `docs/release/1.6.2-build37-user-guide.md`；更新路线图 §19。

**注意**：第一条（人工计时）**必须由人做**，我会准备好计时步骤，但不代替。
