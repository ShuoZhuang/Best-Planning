## 3. 设置首页的两处改法的设计

### 3.1 分组

`SettingsHubEntry` 增加 `group`（枚举，四个值，顺序即 §12 的顺序）：

```dart
enum SettingsGroup { planning, appearance, notification, data }
```

- 顺序固定为 规划与时间 → 外观与交互 → 通知与隐私 → 数据与帮助（§12 原文顺序）；
- **空分组整组不渲染**（未装配的服务本来就不出现在列表里，见现有注释）；
- 组标题用中文短名。

**分组归属由路由器决定**（它知道每一项是什么），页面只按 `group` 分组渲染。

### 3.2 当前关键值

新增一个**只读的值来源**端口（不引入新服务，只是把已有值读出来）：

```dart
/// 设置入口的"当前值"来源。页面不认识任何服务——与它不认识路由同一理由。
typedef SettingsValueReader = Future<String?> Function();
```

`SettingsHubEntry` 增加 `currentValue`（`SettingsValueReader?`）：

- 返回 `null` 或空串时**只显示副标题**（不显示"未设置"这类占位——那对用户没有用，
  与本仓库既有的"没有值就不渲染"口径一致）；
- 值是**异步读**的：首帧先只显示副标题，读到再补上，**不为了一个提示把设置页卡在加载态**；
- 每个入口的当前值必须是**用户能理解的一句**，例如：
  - 规划规则："默认专注 50 分钟"
  - 自动调整："信任自动调整：关闭"
  - 外观："材质：克制"

**值的来源**：组合根（`router.dart`）把已有的服务读出来。**不新建服务、不新建表。**

## 4. 操作式引导：本轮**不交付**（如实说明）

§12 的引导路径 A/B 要求"全新数据环境可以不离开引导完成首个计划"，且两条路径**各有一条集成测试**。

**本轮不做**，理由（不是"没时间"）：

1. 它是**新交互**，会横跨引导页、任务编辑器、生成计划、预览页四五处；
2. 必须先定清若干**产品问题**，例如："引导中途退出算不算完成？"
   "引导里创建的任务与用户自己创建的任务有区别吗？"
   "跳过之后'从设置重新打开'是把引导重放一遍，还是直接进任务编辑器？"
   §12 只写了"跳过不会把教程误记为已完成全部操作"，但没定这些；
3. 在没定清之前就写，结果会是**又一条与真实操作脱节的引导**——正是 §12 要根治的毛病。

**因此本轮交付 §3 的两处（它们判据明确、可验证），并把路径 A/B 登记为需要先定产品问题的下一项。**
这一条**如实标注未完成**，不勾选。

## 5. 强制测试

`test/app/settings_hub_test.dart` 追加：

| 要求 | 测试 |
| --- | --- |
| 四个分组按 §12 顺序出现 | 断言组标题的出现顺序 == 规划与时间 / 外观与交互 / 通知与隐私 / 数据与帮助 |
| **空分组不渲染** | 只给"外观"一组的条目 → 断言其余三个组标题**不出现**（不留空标题） |
| 每个入口展示当前值 | 给一个返回 `默认专注 50 分钟` 的 reader → 断言这句话出现在该入口上 |
| 值为空时只显示副标题 | reader 返回 `null` → 断言不出现该入口的"当前值"占位 |
| 值是异步读到的 | reader 用一个延迟完成的 Future → 先 pump 一帧只见副标题，再 pumpAndSettle 后见当前值（**不卡加载态**） |
| 读取失败不影响列表 | reader 抛异常 → 该入口仍可点、仍显示副标题，**不崩**（与"设置写失败不崩"同一取舍） |
| 既有行为不回归 | 版本号、只列出已装配子页、点击进入正确路由（既有用例全部保留） |
