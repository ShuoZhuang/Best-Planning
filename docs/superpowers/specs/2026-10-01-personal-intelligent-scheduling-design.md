## 1. 文档目的

本文档定义个人智能日程规划软件的产品目标、首版范围、业务规则、功能需求、质量要求和验收标准，作为原型设计、技术选型、开发计划和测试验收的共同依据。

首版优先服务于产品提出者个人使用，同时在数据结构和模块边界上为未来面向其他大学生发布、开发手机 App 和增加云同步保留扩展空间。

## 2. 产品背景与问题

大学生日常事务通常同时来自学业、学生工作、竞赛、科研、社交和个人生活。不同事项具有不同的截止时间、持续时长、重要程度、精力要求和可移动程度。传统待办工具只能记录事项，仍需用户手工判断什么时候完成；传统日历则擅长展示固定日程，但难以自动安排可移动任务。

本产品需要解决以下问题：

1. 将待办事项自动转换为现实、可执行的日程。
2. 在课程、会议、聚会等固定安排之间合理分配任务时间。
3. 当临时事件、延期或实际用时变化时，快速重排后续日程。
4. 保护睡眠、用餐、休息和个人生活，避免以牺牲恢复为代价制造“高效率”。
5. 通过计划与实际投入统计，让用户获得正向反馈并发现可改善之处。
6. 逐步学习个人时间偏好，在保持透明和可控的前提下改善排程质量。

## 3. 产品目标与成功标准

### 3.1 产品目标

- 用户只需提供任务、时长和必要约束，即可获得未来七天的日程建议。
- 用户能理解重要安排和每次调整的原因，并保留最终决定权。
- 突发事件发生后，系统能重排计划且不静默突破硬约束。
- 系统同时考虑长期目标、短期截止压力、精力规律和生活平衡。
- 用户能比较计划时间与实际投入，持续改进时长估算和安排习惯。
- 首版完全本地可用，无需注册账号或依赖在线服务。

### 3.2 成功标准

- 普通任务可在一分钟内完成快速录入。
- 用户能在日历中清楚区分固定日程、自动任务、休息和生活事项。
- 新增突发事件后，系统能给出不违反硬约束的调整方案，或明确说明无可行方案。
- 所有关键移动、拆分和冲突均有可理解的原因说明。
- 用户可以完成、跳过、延期、锁定、手动移动或修正实际用时。
- 统计结果能准确反映不同时间范围和领域的实际投入。
- 程序重启、异常退出、备份恢复和版本升级不应造成已确认数据丢失。

## 4. 产品原则

1. **现实可执行**：不通过虚构空闲时间或过度切碎任务来生成看似完美的计划。
2. **休息优先保护**：睡眠、用餐、固定休息和每日任务上限默认属于硬约束。
3. **用户拥有最终控制权**：自动排程默认先预览后应用；用户可选择信任自动调整。
4. **解释优先**：系统应说明为什么安排、移动或无法安排某项任务。
5. **生活也是计划的一部分**：社交、电影、摄影、游戏等可以进入日程，并获得最低生活时间保障。
6. **本地与隐私优先**：首版数据保存在本机，默认不上传、不投放广告、不依赖在线 AI。
7. **温和反馈**：统计用于认识自己和获得正向反馈，不通过羞辱、扣分或强制连续打卡制造焦虑。

## 5. 用户与典型场景

### 5.1 目标用户

首要用户是同时承担多类事务、希望保持生活平衡并愿意记录任务预计时长的大学生。首版仅支持单用户个人使用。

### 5.2 典型场景

- 用户录入“完成课程论文”，预计 6 小时，允许拆分，截止到周五。系统将其分配为多个专注时段。
- 用户录入每周重复课程。系统不得把其他任务安排到课程时间内。
- 用户临时新增周三晚间聚餐。系统重新计算，并在预览中解释哪些任务被移动。
- 用户出去玩或加班到深夜。系统按实际结束时间保护最低睡眠，并调整次日可移动事项。
- 用户开始任务计时，完成时修正实际用时。统计界面展示计划与实际偏差。
- 系统观察到科研任务在上午完成效果更好，在获得用户确认后提高上午安排科研任务的偏好权重。
- 用户发现本周无法完成全部事项。系统展示可能逾期的任务和所缺时间，并提供可选处理方案。

## 6. 首版范围

### 6.1 首版包含

- Windows 桌面 EXE；
- 本地单用户数据存储；
- 任务、项目、分类及状态管理；
- 固定日程与按周重复日程；
- 作息、用餐、休息、精力区间、每日任务上限设置；
- 生活娱乐最低时间配额；
- 未来七天滚动排程及远期截止压力检查；
- 任务拆分、连续完成、手动锁定和拖动调整；
- 排程调整预览、原因说明及自动调整开关；
- 突发事件、特殊日和次日恢复保护；
- 专注计时、实际时长修正和简短复盘；
- 自选时间范围的数据统计、正向反馈和改善建议；
- 本地、可解释、可撤销的偏好学习；
- Windows 桌面通知和免打扰设置；
- 可选应用密码锁；
- 数据导出、完整备份、恢复和永久清除。

### 6.2 首版不包含

- 多人协作、团队任务或社交社区；
- 在线账号和跨设备实时同步；
- 手机 App；
- 在线 AI 对话规划；
- 第三方日历的双向同步；
- 数据库文件加密；
- 广告、付费订阅和商业化功能。

上述能力可进入后续版本，但不能成为首版核心功能的运行依赖。

## 7. 核心概念与业务对象

### 7.1 任务

任务是需要完成且时间可全部或部分移动的事项。主要字段包括：

- 标题、备注；
- 所属领域、项目和自定义标签；
- 优先级；
- 预计总时长、已投入时长和剩余时长；
- 截止时间或期望完成日期；
- 脑力强度；
- 期望时段；
- 是否允许拆分；
- 若允许拆分，单段最短和最长时长；
- 若不允许拆分，连续完成所需时长；
- 当前状态：收集箱、待安排、已安排、进行中、已完成、已跳过、已取消或已逾期。其中"已安排"与"已逾期"由事实派生，不作为可持久化的字段保存（见技术设计文档 §13.0 的 R12）；
- 是否锁定已安排时间；
- 创建时间、修改时间和唯一标识。

除标题和预计时长外，应尽量减少必填项。缺少可选字段时，系统使用用户默认值。

### 7.2 固定日程

固定日程是默认不可被自动移动的时间占用，例如课程、会议、值班、已确定时间的聚会和电影。主要字段包括开始时间、结束时间、重复规则、地点、提醒方式、所属领域和备注。

### 7.3 保护时间

保护时间包括睡眠、用餐、固定休息以及用户明确标记为不可占用的个人时间。保护时间是硬约束，除非用户针对某一次事件明确授权临时放宽。

### 7.4 自动安排时间块

自动安排时间块是排程引擎为任务生成的具体执行片段。时间块保留来源任务、计划时长、安排原因、锁定状态、版本和确认状态。

### 7.5 实际时间记录

实际时间记录来自专注计时器或用户手动补录，包括开始、结束、暂停、实际时长、关联任务和完成备注。统计以实际记录为主，未记录实际时长时才明确标示数据缺失，不能把计划时长伪装成实际投入。

### 7.6 偏好模型

偏好模型保存用户主动设置和系统学习得到的软约束，例如常用专注长度、任务类别与时段匹配、拆分偏好、建议接受率及精力时段效果。每条学习偏好需保留来源、置信度、生效状态和更新时间。

### 8.4 个人规则与生活平衡

| 编号 | 需求 |
| --- | --- |
| FR-RULE-01 | 支持设置常规睡眠、用餐、固定休息和每日任务时长上限。 |
| FR-RULE-02 | 支持设置一天中的高、中、低精力区间。 |
| FR-RULE-03 | 支持设置每周生活娱乐最低保障时长。 |
| FR-RULE-04 | 娱乐事项仍可设置独立优先级、预计时长和期望日期。 |
| FR-RULE-05 | 支持工作日和周末使用不同规则。 |
| FR-RULE-06 | 用户可针对特定日期创建临时规则，临时规则不覆盖长期默认值。 |

### 8.4.1 默认值与个性化策略

系统不得要求用户在首次使用前从零配置所有规则。首版应提供一套可立即使用的初始值，并在首次引导中集中展示，让用户选择“直接采用”或快速修改。默认值只是起点，不代表适合所有用户，也不作为健康建议。

配置的生效优先级从高到低为：

1. 用户针对某一天或某次事件设置的临时例外；
2. 用户主动设置的长期规则；
3. 用户已经确认采用的学习偏好；
4. 产品提供的初始默认值；
5. 对没有任何规则覆盖的时间使用中性权重。

首版建议初始值如下：

| 设置项 | 初始值 | 个性化方式 |
| --- | --- | --- |
| 高精力区间 | 09:00–12:00 | 可设置多个区间，并分别设置工作日与周末。 |
| 中精力区间 | 14:00–17:00 | 可手动修改；系统可根据完成效果提出调整建议。 |
| 低精力区间 | 19:00–22:00 | 未标记时段为“中性”，不自动认定为低精力。 |
| 常规睡眠 | 23:30–07:30 | 首次引导时优先询问；特殊日可单次覆盖。 |
| 最低睡眠时长 | 7 小时 | 属于恢复保护规则，只有用户可针对单次事件放宽。 |
| 午餐保护时间 | 12:00–13:00 | 可关闭、移动或调整长度。 |
| 晚餐保护时间 | 18:00–19:00 | 可关闭、移动或调整长度。 |
| 默认专注片段 | 50 分钟 | 可按任务类型设置；学习模块可建议更适合的长度。 |
| 片段间短休息 | 10 分钟 | 可按连续专注次数设置更长休息。 |
| 可拆分任务最短片段 | 30 分钟 | 用户可在单个任务上覆盖。 |
| 可拆分任务最长片段 | 90 分钟 | 用户可在单个任务上覆盖。 |
| 每日可移动任务上限 | 6 小时，不含固定课程与会议 | 工作日和周末可分别设置。 |
| 每周生活娱乐最低配额 | 6 小时 | 可设为零，也可按娱乐、社交等类别分别设置。 |
| 调整应用方式 | 先预览、后确认 | “信任自动调整”默认关闭。 |
| 偏好学习 | 开启建议、关闭自动采用 | 用户可完全关闭学习或清除学习结果。 |
| 应用密码锁 | 关闭 | 用户主动设置密码后启用。 |

精力区间不要求覆盖全天。处于未标记时段的任务使用中性精力评分，避免系统因缺少设置而错误降低某个时段的价值。用户可以不接受任何预设，并在首次引导中选择“稍后设置”。

| 编号 | 需求 |
| --- | --- |
| FR-DEFAULT-01 | 所有影响核心流程的设置必须具有明确的初始值或中性回退行为。 |
| FR-DEFAULT-02 | 首次引导应集中展示重要默认值，允许一键采用或快速修改。 |
| FR-DEFAULT-03 | 用户主动设置不得被偏好学习静默覆盖。 |
| FR-DEFAULT-04 | 系统学习到的新偏好默认以建议形式呈现，说明依据和预计影响。 |
| FR-DEFAULT-05 | 只有用户开启“自动采用学习偏好”后，系统才能自动更新软约束权重。 |
| FR-DEFAULT-06 | 自动采用只影响软约束；睡眠、用餐、每日上限等硬约束仍需用户明确修改。 |
| FR-DEFAULT-07 | 所有自动更新均应记录变更前后值，并支持撤销。 |
| FR-DEFAULT-08 | 临时例外不得直接改写长期设置或学习偏好。 |

### 8.5 自动排程

| 编号 | 需求 |
| --- | --- |
| FR-SCHED-01 | 默认详细规划未来七天。 |
| FR-SCHED-02 | 检查七天之外的截止任务，并计算为避免未来拥堵所需的近期投入。 |
| FR-SCHED-03 | 严格遵守固定日程、保护时间、锁定时间块、连续任务和每日任务上限。 |
| FR-SCHED-04 | 综合截止风险、优先级、项目重要性、精力匹配、期望时段、生活配额、切换成本和个人偏好评分。 |
| FR-SCHED-05 | 对允许拆分的任务生成合理长度的片段，避免过度碎片化，并保留片段间休息。 |
| FR-SCHED-06 | 对必须连续完成的任务只选择足够长的完整可用时间块。 |
| FR-SCHED-07 | 相同输入、相同设置和相同引擎版本应产生可复现结果。 |
| FR-SCHED-08 | 排程结果需附带关键选择和移动原因。 |
| FR-SCHED-09 | 用户手动安排与锁定结果优先于系统软偏好。 |

| FR-REPLAN-02 | 预览应列出新增、移动、拆分、取消和可能逾期的事项及原因。 |

| FR-REPLAN-08 | 系统不得自行修改任务截止日期、预计时长或硬约束。 |

### 8.8 专注与实际时间记录

### 8.9 数据统计与正向反馈

| 编号 | 需求 |

## 9. 排程策略

### 9.1 方案

首版采用“硬约束过滤 + 软约束评分优化”的确定性排程方式。大模型不作为核心排程引擎，未来可用于自然语言录入、任务拆解或解释辅助。

### 9.2 排程步骤

1. 读取任务、固定日程、保护时间、用户设置和已锁定时间块。
2. 在未来七天内扣除不可用时间，得到候选可用时间块。
3. 检查更远截止日期，估算近期必须预留的最低进度。
4. 过滤违反硬约束的候选位置。
5. 根据软约束为任务与候选时间块组合评分。
6. 优先安排逾期风险高且可行位置少的任务。
7. 对可拆分任务生成不过度碎片化的时间片段，并保留休息。
8. 校验时间重叠、硬约束、生活配额和任务总时长。
9. 输出候选计划、未安排任务、冲突、调整摘要和解释。

### 9.3 硬约束

- 固定日程不得被自动移动；
- 保护时间不得被自动占用；
- 已锁定时间块不得被自动移动；
- 同一时间不得存在多个互斥事项；
- 连续任务必须获得完整时间块；
- 任意两个任务块之间必须保留设定的片段间休息（默认 10 分钟，见 8.4.1），不区分任务类型。休息占用真实可用的时间，因此当空闲窗口不足以容纳"任务时长 + 休息"时，系统应如实报告缺口，而不是把片段首尾相连排满；
- 每日任务总时长不得超过设定上限；
- 任务片段不得短于用户或系统规定的最短有效时长；
- 用户对某次事件明确授权的临时放宽仅对该次计算有效。

### 9.4 软约束

- 截止时间和逾期风险；
- 用户优先级与项目重要性；
- 脑力强度与精力区间匹配；
- 用户期望时段；
- 生活娱乐最低配额；
- 相邻任务的类别切换成本；
- 同一任务片段的连续性；
- 历史完成率、时长偏差和确认后的个人偏好；
- 为远期任务提前预留的合理进度。

软约束之间的权重应可配置并保存版本，以便解释排程结果和复现历史计划。

> **实现状态说明（2026-10-02）**：本节列出的是需求侧应有的软约束，不等同于已实现能力。截至复核，用户期望时段、同一任务片段的连续性、类别切换成本与移动成本尚未参与排程决策；任务紧迫度由"有效松弛时间"以梯度方式承担，候选位置由覆盖度、精力匹配与碎片化决定。详见技术设计文档 §5.4 与 §13.0（R5、R6、C2）。

### 9.5 不可行计划

当硬约束下不存在完整可行计划时，系统不得伪造成功结果。系统应展示：

- 哪些任务预计逾期；
- 每项任务缺少多少可用时间；
- 主要冲突来自哪些固定安排或约束；
- 哪些用户可选操作能够缓解冲突；
- 每种操作可能造成的影响。

## 10. 页面与信息架构

1. **今日**：当前任务、下一项、今日计划、剩余时间、快捷计时和异常提示。
2. **收集箱/任务**：快速录入、任务详情、搜索筛选、项目与分类管理。
3. **日历**：日视图和七日周视图，展示固定日程、任务块、休息与生活事项。
4. **调整预览**：变更摘要、逐项原因、冲突方案、确认或撤销。
5. **专注**：计时、暂停、结束、实际时长修正和完成备注。
6. **统计与复盘**：时间范围、筛选器、领域分布、趋势、计划实际对比、成就和建议。
7. **偏好与设置**：作息、精力、生活配额、通知、自动调整、学习偏好和密码锁。
8. **数据管理**：导出、备份、恢复、迁移信息和永久清除。

## 11. 系统结构

### 11.1 界面层

负责展示与用户操作，不直接实现排程规则。界面通过稳定的业务接口读取和修改数据。

### 11.2 业务层

负责任务状态、重复日程、计时、统计、通知、特殊日和权限检查，为桌面界面和未来移动端提供一致的业务定义。

### 11.3 排程引擎

作为独立模块接收标准化输入，输出候选计划、冲突和解释。引擎不直接操作界面，也不在计算失败时覆盖现有计划。

### 11.4 本地数据层

负责持久化任务、日程、时间块、实际记录、设置、偏好、排程版本和变更历史，并提供事务、迁移、备份及恢复能力。

## 12. 数据流

1. 用户录入或修改任务、日程及个人规则。
2. 业务层校验输入并写入本地数据库。
3. 触发排程时，业务层生成当前状态快照并传给排程引擎。
4. 排程引擎返回候选计划、冲突和解释，不直接修改已确认计划。
5. 系统展示调整预览；用户确认后，业务层以一次事务保存新计划和变更历史。
6. 用户执行任务并记录实际时间；统计模块基于已保存记录生成指标。
7. 偏好模块根据一段时间内的行为生成建议，用户确认后才更新排程软权重。

## 13. 异常与边界处理

- 排程计算失败：保留旧计划，展示错误和重试入口。
- 输入时间冲突：阻止静默覆盖，指出冲突事项并提供编辑入口。
- 重复日程跨越日期或时区变化：以本机当前时区保存和展示，并进行边界测试。
- 计时期间异常退出：保存心跳或开始状态，重启后请求用户确认实际结束时间。
- 备份损坏或版本不兼容：拒绝覆盖现有数据并说明原因。
- 磁盘空间不足或数据库写入失败：提示用户并保持最后一次完整事务状态。
- 系统时间被大幅修改：暂停自动应用，提示用户确认时间变化后重新计算。
- 固定日程与最低睡眠冲突：明确报告风险，由用户处理，不声称计划已满足全部约束。

## 14. 非功能需求

### 14.1 可用性

- 常用操作应可通过清晰的键盘和鼠标路径完成。
- 快速录入只要求最少字段，高级选项逐步展开。
- 系统建议、统计和冲突提示使用清楚、中性、非评判性的中文。

### 14.2 性能

- 常规任务和日程规模下，打开今日页与周视图不应出现明显等待。
- 排程计算应支持取消；计算期间不阻塞查看现有计划。
- 大量历史统计采用增量汇总或缓存，但缓存不得造成数据不一致。

具体性能数值在技术方案确定并建立代表性数据集后纳入开发计划，不在本需求文档中虚构设备无关的时间承诺。

### 14.3 可靠性

- 核心写入使用事务，避免只保存部分调整。
- 每次应用新计划前保留可回退的上一版本。
- 数据库结构升级必须包含迁移与回滚测试。
- 同一排程输入可复现，便于定位问题。

### 14.4 隐私与安全

- 首版采用本地优先模式，不要求登录。
- 应用密码锁用于阻止他人直接进入软件，但文案必须说明其不等同于数据库加密。
- 敏感内容不得出现在普通诊断日志中。
- 用户可查看数据保存位置并控制备份去向。

### 14.5 可扩展性

- 业务模型不依赖桌面界面实现。
- 核心记录具备全局唯一标识和修改时间。
- 排程引擎接口与存储实现解耦。
- 为以后手机端和云同步预留冲突版本字段，但首版不实现同步逻辑。

## 19. 已确认决策

1. 首版为 Windows EXE，未来考虑手机 App。
2. 首版本地优先，无需账号与云同步。
3. 支持固定日程和按周重复日程。
4. 采用未来七天滚动规划，并检查更远截止日期。
5. 长任务默认可拆分，也支持必须连续完成。
6. 睡眠、用餐、固定休息和每日任务上限为硬约束。
7. 社交活动和个人娱乐均纳入计划，并同时考虑事项优先级与生活时间配额。
8. 无法完成所有事项时明确报告冲突，由用户选择解决方式。
9. 排程考虑用户精力区间和任务脑力强度。
10. 调整默认先预览确认，并提供“信任自动调整”开关。
11. 同时记录计划时长和实际时长，统计范围由用户选择。
12. 采用可解释、可撤销的渐进式偏好学习。
13. 晚归、加班等作为单日例外，并提供次日恢复保护。
14. 首版提供可选应用密码锁；数据库加密放在发布准备阶段。
15. 核心排程采用约束规则与评分优化，不由大模型直接决定日程。
16. 所有关键设置提供默认值或中性回退；用户主动设置优先，学习偏好默认先建议后采用。
