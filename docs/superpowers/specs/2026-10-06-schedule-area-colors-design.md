# 日程领域配色设计

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 1.1 |
| 文档日期 | 2026-10-06 |
| 文档状态 | 用户已确认设计，待书面复核；§7 为同日视觉纠偏增补 |
| 适用范围 | 今日页、七日日历、单日详情、领域与项目设置 |
| 当前源码版本 | `1.4.2+22`，尚未发布 |

## 1. 目标

日程卡片不再用“固定日程、保护时间、可移动任务、生活”决定颜色。新的颜色含义是事项所属领域；保护时间以及没有领域的事项使用三种单独配置的颜色。

完成后，同一条事项在今日页、七日日历和单日详情中必须保持同色。卡片上的分类文字只显示领域或特殊分类，不再组合成“学业 · 任务”。事项性质继续由现有图标表达，并写入无障碍语义。

## 2. 已确认的分类规则

| 事项 | 可见分类文字 | 颜色来源 |
| --- | --- | --- |
| 有领域的可移动任务 | 领域名称，例如“学业” | `areas.color` |
| 有领域的固定日程 | 领域名称，例如“科研” | `areas.color` |
| 无领域可移动任务 | “无领域任务” | 可配置的特殊颜色 |
| 无领域固定日程 | “无领域固定日程” | 可配置的特殊颜色 |
| 午餐、晚餐、固定休息等保护区间 | “保护时间” | 可配置的特殊颜色 |

若事项保存了一个已经不存在的领域 ID，界面按“无领域任务”或“无领域固定日程”处理；不能显示失效 ID，也不能回退到旧的类型配色。

`ScheduleItemKind.life` 当前没有生产数据来源。若测试夹具或旧数据产生该类型，有领域时仍按领域显示；没有领域时归入“无领域任务”。

## 3. 不采用的方案

### 3.1 把特殊分类伪装成领域

保护时间、无领域任务和无领域固定日程不写入 `areas`。伪造领域会让它们出现在项目归属、统计筛选和任务表单里，用户还能把项目挂到“保护时间”下面，业务含义会被破坏。

### 3.2 每个页面自行取色

今日页、周视图和日视图不能各自维护颜色分支。三个页面展示的是同一批 `ScheduleViewItem`；若页面自己判断，后续新增分类时很容易只改到其中一处。

### 3.3 自由取色器

首版只提供项目设计系统中的低饱和固定色板。自由取色会产生低对比颜色，也可能让日程卡片比主按钮和当前状态更醒目。固定色板仍允许重复选择；系统不强制所有分类颜色唯一。

## 4. 数据结构与持久化

### 4.1 领域颜色

沿用 `PlannerArea.color` 和数据库现有的 `areas.color`，不增加数据库列。

历史数据中的 `color == 0` 表示用户从未选过颜色。读取时按 `sortOrder` 从默认色板取值；用户选色后保存真实 ARGB 整数。纯黑为 `0xff000000`，与未设置值 `0` 不冲突，不过固定色板不会提供纯黑。

新建领域优先选择当前领域尚未使用的色板颜色；全部用过后按排序循环。该规则只决定初始值，不会在后续自动改色。

### 4.2 三种特殊颜色

新增不可变值对象 `ScheduleSpecialColors`：

```text
protectedTimeArgb
unassignedTaskArgb
unassignedFixedArgb
```

三项以一个 JSON 对象写入现有设置表，键名为 `schedule.colors.v1`。缺少键、JSON 损坏、字段不是整数或 ARGB 值无效时，读取端逐项使用默认值，不让整个日历加载失败。

这三种颜色不写入领域表，也不进入任务、日历事件或计划块。修改颜色只改变展示，不触发重新排程，不修改统计事实。

### 4.3 默认色板

恢复固定领域色板文件，并在原有六色基础上补足可区分的深色界面颜色。默认的五个领域、保护时间和两种无领域分类拿到互不相同的初始颜色。

所有色板项必须满足两条检查：色点或图标与深色表面的图形对比度不低于 3:1；卡片正文仍使用现有主文字令牌，普通文字对比度不低于 4.5:1。

## 5. 统一解析流程

新增日程颜色服务，依赖 `WorkspaceRepository` 与 `SettingsRepository`。它一次读取领域列表和特殊颜色设置，生成 `ScheduleColorCatalog`。

目录中的每个分类包含：

```text
categoryKey
label
colorArgb
sortOrder
```

`RepositoryScheduleViewSource` 在读取固定日程、保护区间和计划块时调用同一个目录，将解析结果写进 `ScheduleViewItem`：

```text
categoryKey
categoryLabel
categoryColorArgb
categorySortOrder
```

页面只消费这些字段，不再根据 `ScheduleItemKind` 选择卡片颜色。`kind` 仍负责图标、拖动资格、编辑入口和无障碍类型说明。

该边界让取色逻辑只有一个实现位置；今日页、七日日历和单日详情即使使用不同布局，也不会出现同类事项颜色不一致。

## 6. 领域设置界面

“领域与项目”页增加“日程颜色”说明，并把颜色入口放在对应条目旁边。

每个领域行显示一个当前色点和“更换颜色”按钮。三种特殊分类放在领域列表之后，名称固定为：

- 保护时间
- 无领域任务
- 无领域固定日程

点击颜色入口后打开同一个色板对话框。对话框标题包含正在修改的分类名称；每个色块提供颜色名称、选中标记、键盘焦点和至少 44×44 像素的点击范围。用户选中颜色后立即保存并关闭对话框，保存失败时保留原色并在当前页提示。

项目行不显示颜色，因为项目继承所属领域的展示色。生活开关仍只控制生活配额与统计口径，不自动改成紫色，也不限制用户选色。

## 7. 卡片表面：不透明深色派生色（2026-10-06 视觉纠偏）

§5 让三个页面拿到了同一个分类色，但当时把"怎么用这个颜色画卡片"留给了页面自己决定，于是三个页面各写了一套透明度：今日页 `alpha 0.10`、七日历与单日详情 `alpha 0.18` 填充加 `alpha 0.72` 原色描边。结果是卡片发白、亮度偏高、描边发光，同一个事项在三个页面深浅不同，而且玻璃模式越激进卡片越被冲淡。本节把这件事收回来，**取代**任何"页面可以自行选择卡片透明度"的描述。

### 7.1 一个共享派生器，三个页面只消费结果

卡片颜色只有一个来源，函数签名固定为：

```text
scheduleCategoryCardStyle(Color categoryColor) -> ScheduleCategoryCardStyle(accent, fill, border)
```

今日页、七日日历、单日详情都必须调用它，不得在页面内复制混色公式，也不得再对分类色叠加透明度。实现位于 `lib/features/calendar/schedule_category_card_style.dart`。

### 7.2 固定公式

```text
accent = categoryColor
fill   = toneAtLuminance(categoryColor, 0.034)
border = toneAtLuminance(categoryColor, 0.065)

toneAtLuminance(c, target) =
  取 c 的色相；饱和度 = min(饱和(c), 0.60)；二分求解明度，使 computeLuminance() == target
```

`fill` 与 `border` **必须完全不透明**：半透明填充会让底下的玻璃背景透上来，这正是"卡片发白"的根因，也是同一张卡片在四种材质模式下观感不同的原因。以学业蓝 `#2f86ff` 为例，结果是强调 `#2f86ff`、填充 `#17345b`、描边 `#20487f`。

**为什么不是"往表面色按比例混"**：这是本设计改过的一次**公式级**修订，理由值得完整留下。比例式派生（`lerp(surface, category, t)`）把"变深"和"掉彩度"绑死了——`t` 越小越靠近深蓝灰的表面色，**饱和度同比掉光**：

| 阶段 | 公式 | 琥珀色填充 | HSV 饱和度 | 八色填充亮度 | 用户反馈 |
| --- | --- | --- | ---: | --- | --- |
| 首版 | `lerp(…, 0.26)` | `#4e473c` | 23% | 0.040 ~ 0.062 | "卡片仍然偏淡" |
| 二次 | `lerp(…, 0.18)` | `#3c3b39` | 7% | 0.0325 ~ **0.0447** | "配色的主要问题是太亮了" |
| 三次 | `lerp(…, 0.12)` | `#2f3336` | **13%** | 0.0254 ~ 0.0326 | **"颜色比老版的浅还淡，看着还亮"** |
| 当前 | `toneAtLuminance` | `#463011` | **83%** | **0.0335 ~ 0.0348** | —（性格与旧版一致） |

三次降比例之所以都没解决，是因为**降比例只能让卡片更灰**：`0.12` 的琥珀色 `#2f3336` 是 R47 G51 B54，一块中性灰——既没有彩度（"淡"），又是被提亮的灰（"浅""亮"）。而旧版卡片底色的实测饱和度是 **58% ~ 79%**，是"**深 + 有彩度**"。要同时满足"深"和"有彩度"，色相/彩度与明度必须**分开控制**。

**这版公式的两个取舍**：

1. **明度用二分求解，而不是固定一个明度值**。同样的明度下黄色比蓝色亮得多，固定明度会让八张卡的重量天差地别（实测亮度会散到 `0.0108 ~ 0.0274`，2.54 倍）。求解到统一亮度后实测为 `0.0335 ~ 0.0348`（1.04 倍）。求的是 `computeLuminance()`——也就是验收测试所用的同一个量，避免"算的是一个、测的是另一个"。
2. **饱和度取 `min(原色饱和度, 0.60)` 而不是直接套 `0.60`**：本来就灰的色板色（灰蓝 `#7f92b2`）不该被硬拉成彩色，否则又会变成"分类之间差别过大"。

**明度一致的代价要说清**：八张卡的**色相差**会比旧版大（实测 RGB 曼哈顿距离最大 164，旧版今日页只有 23、七日页 83）。这不是公式的缺陷，而是**语义决定的**——旧版的卡片底色只服务三种任务类型，且刻意挑成几乎同色；现在它要承载八个领域色。分类身份因此仍由左侧强调条、图标与图例共同承担，卡片底色只是"同一家族的深浅"。

`border` 用同一规则、目标亮度 `0.065`：落在旧版描边实测 `0.0420 ~ 0.0907` 的中段，可辨认但不发光。

公式不接受页面、任务类型或玻璃模式参数：这些维度正是让颜色分叉的原因。任务类型继续由图标表达，不再参与配色。

公式不接受页面、任务类型或玻璃模式参数：这些维度正是让颜色分叉的原因。任务类型继续由图标表达，不再参与配色。

### 7.3 领域原色只用于小面积强调与图例

`accent`（即分类原色）只允许出现在：卡片左侧强调条、时间轴圆点、事项性质图标、图例色点、色板对话框、以及"当前安排／今日容量"的小面积标识。卡片表面与完整边框一律使用 `fill` / `border`。

### 7.5 验收标准

| 检查项 | 要求 |
| --- | --- |
| 八色精确值 | 逐格等于 §7.4 的常量表 |
| 填充亮度 | `fill.computeLuminance() <= 0.0428`（旧版实测最亮卡片；**不得比旧版亮**） |
| 强调色对比度 | `accent` 对 `fill` 不低于 `3:1` |
| 正文对比度 | `PlannerPalette.textPrimary` 对 `fill` 不低于 `4.5:1`；`textSecondary` 不低于 `3:1` |
| 跨页面一致 | 同一事项在今日、七日历、单日详情的 `accent`/`fill`/`border` 逐值相等 |
| 跨材质一致 | 无玻璃、克制、激进、极致四种模式下卡片 `fill`/`border` 的 ARGB 完全相同 |
| 分类信号 | 领域文字、保护盾牌、任务／固定日程图标必须保留；颜色不是唯一分类信号 |

## 8. 今日页

今日页卡片使用 `categoryColorArgb` 绘制左侧强调线、时间点、图标；卡片表面与完整边框使用 §7 的不透明派生色。分类文字改为 `categoryLabel`：有领域时只显示“学业”等领域名，无领域时显示对应特殊分类。

标题区图例从当天实际条目生成并去重。领域按领域排序显示，随后是当天出现的保护时间、无领域任务和无领域固定日程。当天没有出现的分类不占标题空间；图例换行时不得挤压页面标题。

“今日容量”不再用固定、保护、任务三种旧颜色。它按同一分类目录汇总分钟数，容量条、色点和列表都使用卡片对应颜色。固定或可移动的性质不在这里重复统计，卡片图标仍可区分它们。

## 9. 七日日历与单日详情

七日日历在标题区显示当前七天实际出现的分类图例，排序规则与今日页相同。卡片顶部保留现有事项性质图标，旁边只显示 `categoryLabel`。

单日详情使用同一颜色字段。卡片副标题显示时间、分类名称和既有解释文本，不再显示固定/任务类型文字；固定日程的编辑、删除和调整归属能力不变。

拖动只允许 `ScheduleItemKind.task`，领域配色不能改变这一规则。用户把任务拖到另一日时，颜色和分类保持不变。

## 10. 可访问性

颜色不是唯一信息来源：卡片始终显示分类名称，并保留固定日程、任务、保护时间各自的图标。语义标签包含标题、事项性质、分类名称以及起止时间，即使用户看不见颜色也能判断内容。

色板按钮使用 Flutter `Semantics` 和 `Tooltip`，例如“蓝色，当前已选择”或“设为青绿色”。键盘焦点顺序按色板视觉顺序排列，选中状态不能只用边框颜色表达，还要显示勾选图标。

## 11. 刷新与失败处理

颜色设置保存后，领域页立即刷新当前色点。返回今日页或日历页时重新订阅日程数据并读取最新目录；本轮不增加跨页面实时广播。

领域颜色保存失败时不更新本地列表。特殊颜色设置读取失败时使用默认值；写入失败时显示简短提示，不暴露设置表键名或内部异常。

分类目录无法找到领域时执行第 2 节的无领域回退。任意颜色问题都不能阻断日程内容加载。

## 12. 测试范围

### 12.1 颜色规则与服务

- 历史领域颜色为 0 时按排序取默认色；
- 新领域优先使用未占用颜色，色板耗尽后循环；
- 三种特殊颜色可以分别保存、读取和恢复默认值；
- 损坏设置只让对应字段回退，不影响其他字段；
- 色板在深色表面达到约定的图形对比度。

### 12.2 数据源

- 有领域任务与有领域固定日程得到相同领域色和领域名；
- 无领域任务、无领域固定日程、保护时间分别得到三个特殊分类；
- 失效领域 ID 按事项性质回退；
- 改色后重新读取数据得到新颜色，但日程时间和归属不变。

### 12.3 界面

- 领域页能修改领域颜色和三种特殊颜色；
- 色板提供可读名称、选中图标和足够点击尺寸；
- 今日页、七日日历和单日详情对同一条事项渲染同色；
- 卡片只显示领域或特殊分类，不显示“领域 · 任务”；
- 今日容量按领域和特殊分类汇总；
- 图例只列当前时间范围内出现的分类，并保持稳定顺序；
- 图标、语义标签和拖动限制仍按事项性质工作。

## 13. 版本处理

本功能并入 `1.4.0` 批次，因此语义版本仍为 `1.4.0`，不会因为同一批次多一项功能就抬到 `1.5.0`。该批次后来以 `1.4.1+21` / MSIX `1.4.1.0` 作为候选构建交付。

§7 的视觉纠偏是同一批次内**只有修复**的后续改动（不新增功能、不改数据、不改包身份），因此按 Patch 抬第三段：应用 `1.4.2+22`，MSIX `1.4.2.0`，构建号继续全局递增而不归零。判定依据与规则全文见工作区 `版本号规则.md` 与 `docs/release/version-policy.md`。

升级必须能从已安装的 `1.4.1.0` 原位覆盖，且保留本地数据；用户验收前标记为候选构建，不宣称正式发布。
