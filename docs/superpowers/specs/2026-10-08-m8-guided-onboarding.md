# M8 补充规格：操作式首次引导（用户 2026-10-07 定案）

> 冻结用户 2026-10-07 给出的规则。**规则原文以用户表述为准，本文件只做落地拆解**，
> 不改动任何一条语义。路线图：§12「引导路径」；验收记录：`docs/testing/m8-acceptance.md`。
>
> **不抬版本、不单独发布**（§3／§14）。这是 `1.6` 发布线内的同一批次，
> MSIX 第四段按"同批次重打包"递增。

## 1. 用户定的规则（逐条照录，作为验收判据）

### 1.1 三个状态不是一回事

```
未开始 → 进行中 → 已完成
                ↘ 已跳过
```

**「退出」「跳过」「完成」是三个不同的状态。** 退出不得冒充完成。

### 1.2 中途退出

关闭窗口、返回主界面或程序异常退出，**都不写入"已完成"**。

系统保存：
- 当前进行到哪一步；
- 已经确认的默认设置；
- 已经成功创建的任务或导入的课程；
- **尚未应用的计划预览不保存为正式计划**。

下次启动显示：

```
上次的新手引导还没有完成
[继续引导] [重新开始] [暂时跳过]
```

「重新开始」**只重置引导进度**，不能删除已经创建的真实任务、课程或已确认计划。

### 1.3 引导中创建的任务

与普通任务**没有任何业务区别**：
- 使用同一任务表；
- 使用同一套默认值和校验；
- 可以编辑、删除、完成、拆分和参与重排；
- 统计和日历中正常显示；
- 退出引导后仍然保留。

界面可以写"在引导中创建"，但**不要增加特殊任务类型**，也**不要偷偷添加永久标签**。

### 1.4 点击「跳过」

点击「跳过引导」后：
- 状态记录为**「已跳过」**；
- 后续启动**不再自动弹出**引导；
- 已经创建的任务、课程和已应用计划**继续保留**；
- **尚未确认的表单或计划预览丢弃**；
- 从设置再次打开时，进入**引导首页**，而不是直接进入任务编辑器。

引导首页继续提供：

```
[创建第一个任务]
[导入课表]
[了解主要界面]
```

如果用户**已经有任务**，文案改为「再创建一个任务」，**避免假装这是第一次使用**。

### 1.5 计划日期

引导生成的计划**必须使用用户本地时间**：

```
规划起点：今天本地 00:00
规划范围：今天 + 后续 6 个自然日
```

例如 2026-10-07 进入引导 → 窗口 `2026-10-07 ～ 2026-10-13`。

**但这不代表一定把任务塞进今天。** 如果今天已经很晚、没有空档或不满足最早开始时间，
首个任务可以安排到明天或之后。

**重新打开引导时应以重新生成当日的日期为准**，不能继续使用第一次进入引导时保存的旧日期。

### 1.6 这套规则要保证的四件事（用户原话）

> 退出不会冒充完成，跳过不会反复打扰，重新打开不会误创建任务，
> 而引导产生的所有真实数据都遵守正常产品规则。

## 2. 落地拆解

### 2.1 状态与存储

新增 `OnboardingProgress`，落在 `SettingsRepository`（沿用既有的 `onboarding.*` 键空间）：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `onboarding.state.v2` | `notStarted` / `inProgress` / `completed` / `skipped` | 四个状态 |
| `onboarding.step.v2` | 步骤标识（字符串） | 仅 `inProgress` 时有意义 |
| `onboarding.schemaVersion` | 整数 | **保留既有键与语义**：schema 抬高时增量重问关键默认值 |

**为什么新增 v2 键而不是改 `schemaVersion` 的含义**：既有键的语义是"关键默认值确认到哪一版了"，
它已经被 `planner_app.dart` 与测试依赖。把"是否完成引导"塞进同一个整数会让两件事耦合——
schema 从 1 抬到 2 时，用户会**因为新增了一个默认值而被当成"从没引导过"**。
两个维度分开存，各自演化。

**读取失败/值不认识时一律回落到 `notStarted`**（与 `WeekViewPreferenceService` 同一取舍）。

### 2.2 启动分派（`planner_app.dart`）

| 状态 | 启动时表现 |
| --- | --- |
| `notStarted` | **直接进引导首页**（不弹"继续"询问） |
| `inProgress` | 显示「上次的新手引导还没有完成 [继续引导] [重新开始] [暂时跳过]」 |
| `completed` | 进主界面（然后走既有教程闸门） |
| `skipped` | 进主界面，**不再自动弹出** |

**「暂时跳过」与「跳过引导」的区别**（用户表格里两个词都出现了，必须分清）：
- 询问框里的**「暂时跳过」**＝本次先不引导，状态**保持 `inProgress`**，下次启动仍会问
  （对应"退出不会冒充完成"：它没有完成任何东西，也不该把进行中的进度抹掉）；
- 引导里的**「跳过引导」**＝状态改为 `skipped`，此后不再自动弹出（§1.4）。

### 2.3 引导首页（`onboarding_home_page.dart`）

```
[创建第一个任务] / [再创建一个任务]   ← 已有任务时换文案
[导入课表]
[了解主要界面]
```

- **「已有任务」的判据**：`TaskRepository` 里**存在任何任务**（含已完成／已取消）。
  用"曾经创建过"而不是"还有未完成的"，因为要表达的是"你不是第一次用了"。
- 「了解主要界面」→ 既有的截图教程（**不删除任何现有帮助材料**）。

### 2.4 两条路径

**路径 A**：创建第一个任务 → 生成计划 → 查看调整原因 → 应用计划。
**路径 B**：导入课表 → 确认识别结果 → 创建一个任务 → 生成计划。

两条都**复用既有页面与服务**，不新建第二套任务编辑器或导入向导。

### 2.5 计划窗口

用 `zones.localMidnightToUtc(本机今天, timeZoneId)` 作起点，`+7 天` 作终点。
**每次进入引导时重新计算**，不读上次存下的日期（§1.5 最后一句）。

## 3. 强制测试

### 3.1 状态机（纯逻辑）

| 要求 | 测试 |
| --- | --- |
| 四个状态各自的读/写 | 往返一致；未知值回落 `notStarted` |
| **退出不写"已完成"** | 从 `inProgress` 退出后仍是 `inProgress` |
| 「暂时跳过」保持 `inProgress` | 不变成 `skipped`、也不变成 `completed` |
| 「跳过引导」变 `skipped` | 且**不清除**已创建的任务 |
| 「重新开始」只重置进度 | 进度归零，**任务/课程数不变** |
| schema 抬高不改变引导状态 | 两个维度互不干扰 |

### 3.2 启动分派（Widget）

| 状态 | 期望 |
| --- | --- |
| `notStarted` | 直接是引导首页，**没有**"继续引导"询问 |
| `inProgress` | 有询问框与三个按钮 |
| `completed` | 屏幕上没有引导首页 |
| `skipped` | 没有引导首页、**也没有**询问框 |

### 3.3 引导首页文案

- 没有任何任务 → 「创建第一个任务」
- **存在已完成/已取消的任务** → 「再创建一个任务」（不能只看"未完成"）

### 3.4 计划窗口（纯逻辑）

- 起点是**本机今天零点**（不是 UTC 今天）；
- 长度 7 天；
- **重新进入时用新的今天**，不沿用旧日期。

### 3.5 任务无特殊标记

- 引导里创建的任务在任务表里与普通任务**字段完全一致**（没有 `isOnboarding` 之类）；
- **没有**被悄悄加上任何标签。
