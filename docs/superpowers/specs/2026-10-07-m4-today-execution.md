# M4 规格：今日执行与调整信任

> 冻结路线图 §8 的边界。路线图：`docs/superpowers/plans/2026-10-07-product-experience-master-roadmap.md`。
> **不重新实现专注或重排引擎**（§8「已有能力」）；**不抬版本、不单独发布**（§3）；
> **不得带入 M5 及以后**（§14）。

## 1. 用户结果（§8 原文）

今日页不再只是日程查看器。用户能从当前安排直接开始专注、完成、延后、跳过、调整或查看详情；
临时聚会、晚归和加班引发的重排先给出清楚的变化预览。

## 2. 现状（审计结论，2026-10-07）

`lib/features/today/today_page.dart`（820 行）**当前是一个纯展示页**：构造参数只有
`source` / `day` / `toLocal`，卡片上**没有任何动作**。逐条对照 §8：

| §8 要求 | 现状 | 差距 |
| --- | --- | --- |
| 当前安排卡片提供「开始专注」和「完成」主动作 | ❌ 卡片只显示标题、时间、分类、已完成图标 | **缺失** |
| 待执行卡片提供 查看详情 / 延后 / 锁定 / 请求调整（用菜单控制密度） | ❌ 无动作 | **缺失** |
| 今日页只显示所选日期当天的安排 | ✅ `source.watch(day, day+1)` | 无（需测试钉住） |
| 顶部重排提示支持关闭；关闭只隐藏提示，**不取消待确认方案** | 需核实是否有该提示 | 待核实 |
| 调整预览按 新增/移动/拆分/未安排/保护时间变化 分组，并显示原时间、目标时间、原因 | ⚠️ `plan_preview_page.dart` 只有 `added`/`moved`/`split`/`removed` 四种，`PreviewChange` **只有 `reason`，没有原时间与目标时间** | **缺失两项分组与两个字段** |
| 信任自动调整只动软约束内的可移动任务；固定日程/保护时间/锁定块/连续任务不被静默突破 | ✅ 既有服务 | 需测试钉住 |
| 临时晚归或加班用**单日例外**，显示对次日睡眠、可用时间、逾期风险的影响；长期作息不变 | 需核实既有页面 | 待核实 |
| 调整失败保留当前已确认计划，并给出缺少时间、冲突来源与可选处理办法 | 需核实 | 待核实 |

**结论**：本里程碑的核心是**给今日页补上执行动作**，并把调整预览补到 §8 要求的分组与信息量。
**不重新实现**专注计时与重排引擎——那两块已存在。

## 4. 实施范围

### 4.1 计划块 → 任务的可达性（前置）

今日页要能"完成/延后/查看详情"，就必须从视图条目找到它**属于哪个任务**。
`ScheduleViewItem` 目前只把任务 id 藏在 `id` 的 `'block:'` 前缀之后，且**没有 `taskId` 字段**。

**做法**：给 `ScheduleViewItem` 增加**可选** `taskId`，由 `schedule_view_source.dart` 在构造任务块时
填入（那里本来就有 `block.taskId`）；固定日程与保护时间不填。
> 只加一个可选字段，不改既有字段语义，三个视图（今日／周日历／单日）都能用。

### 4.2 今日页的执行动作

**当前安排卡片**（正在进行的任务块）：

- **「开始专注」**——主动作。§8 退出条件要求"从今日页开始专注不超过两次点击"，
  因此这个按钮必须**直接**在卡片上，不藏进菜单。
- **「完成」**——主动作。

**其它卡片**（待执行／已完成）：

- 用**一个菜单**收拢，避免每张卡片堆满按钮（§8 明确要求"动作密度用菜单控制"）：
  - 查看详情
  - 延后
  - 请求调整（→ 排程提案预览，落地为既有的 `RequestedMove` 路径）
  - 锁定（仅任务块；复用既有 `lock` 语义）

**"跳过"**：§8 的"跳过"在领域模型里**没有对应字段**（任务状态只有 open/completed/cancelled，
`cancelled` 是"不做了"而不是"今天这次跳过"）。**本里程碑不发明新的持久化状态**；
实现为「本条不再出现在今天的时间线里，但不改任务状态」需要新的存储语义，
已登记在 §7「未做项」，**不偷偷加**。

### 4.3 今日页只显示当天

断言 `watch(day, day+1)` 且**渲染出的条目都在该区间内**；跨天块按既有 `overlaps` 语义处理，
并加测试钉住"不混入未来几天"。

### 4.4 重排提示可关闭（会话内）

- 顶部提示支持关闭；
- **关闭只隐藏这条提示，不取消待确认方案**；
- 关闭后**同一会话内不再重复出现**；**重新生成的新方案仍会提醒**。
> "同一会话"的范围是**本次页面生命周期**（`State`），不做持久化——持久化会让"下次打开也看不到"
> 变成静默丢方案。

### 4.5 调整预览补齐分组与信息（前置字段）

- `PreviewChangeKind` 增加 `unplanned`（未安排）与 `protectedTimeChanged`（保护时间变化）；
- `PreviewChange` 增加 `fromLabel` / `toLabel`（原时间／目标时间），保留 `reason`；
- 分组渲染：新增 / 移动 / 拆分 / 未安排 / 保护时间变化。

> **这是本里程碑里最大的一块**，会触及 `plan_preview_page.dart` 与它的测试（265 行 + 测试）。
> 若某一轮余量不足，**先交付 4.1～4.4 并如实标注 4.5 未完成**，不留半成品。

## 5. 强制测试

| 要求 | 测试 |
| --- | --- |
| 今日页开始专注 ≤ 2 次点击 | 点击计数：从页面进入 → 点「开始专注」 = 1 次；断言回调/导航被触发一次 |
| 完成/延后后时间线、任务状态一致 | 用真实服务与内存仓储：点完成后 `TaskService` 的任务状态变 `completed`，且时间线重建后显示已完成 |
| 只显示当天 | 造跨两天的数据，断言今日页不含次日条目 |
| 重排提示可关闭且不取消方案 | 关闭后提示消失、方案仍在；同一会话不再出现；新方案会再次提醒 |
| 预览分组与时间字段 | 五类分别渲染；每类显示原时间与目标时间 |
| 自动调整不突破硬约束 | 固定日程/保护时间/锁定块/连续任务在自动调整后位置不变 |
| 取消预览不改任何东西 | 进预览 → 取消 → 计划、锁定块、任务原始信息逐项不变 |

## 6. 退出条件（§8）

- [ ] 从今日页开始专注**不超过两次点击**。
- [ ] 完成、延后和跳过后，今日时间线、任务状态和统计记录一致。
      > **"跳过"见 §4.2：领域模型没有这个状态，本里程碑不发明它。** 若最终未实现跳过，
      > 这一条**如实标注未完成**，不勾选。
- [ ] 关闭提示后不会反复在同一会话中出现，重新生成的新方案仍会提醒。
- [ ] 晚归场景不会永久修改常规作息。
- [ ] 预览取消后，当前计划、锁定块和任务原始信息不变。
- [ ] 自动调整与预览确认两条路径**各有集成测试**。
- [ ] `flutter analyze` 0 问题、`dart format` 0 改动、全量 `flutter test` 全绿。
- [ ] M4 章节写入 `docs/release/1.6.2-build37-user-guide.md`；更新路线图 §19。
