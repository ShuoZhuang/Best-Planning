# 任务领域、时间约束与课表导入设计

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 文档日期 | 2026-10-05 |
| 文档状态 | 用户已确认设计，待实施计划 |

## 1. 背景与目标

当前实现把任务的领域归属完全建立在“任务 → 项目 → 领域”的间接关系上。没有项目的任务无法属于任何领域，因此任务创建时不能直接选择“学业、科研、竞赛、工作、生活”，统计与生活配额也无法准确覆盖未归属项目的任务。同时，任务只有截止时间和期望时段，缺少“不得早于某时开始”的硬约束。

固定日程当前支持每周重复与截止日期，但没有隔周规则、单双周语义、学期与节次模板，也没有从课表图片导入的入口。

本设计解决以下问题：

1. 明确区分领域和项目，并让任务先选领域、后选该领域下的可选项目。
2. 新建项目时明确选择所属领域；在任务表单内新建时继承当前领域。
3. 默认领域补齐“竞赛”和“工作”。
4. 为任务增加最早开始时间，作为排程硬约束。
5. 为周期日程增加起止范围和隔周能力，支持单双周课程。
6. 提供本地优先、可校对、可预览、可整批撤销的课表图片导入。
7. 修复深色界面的低对比文字与过密设置卡片。

## 2. 设计原则

- **领域是长期分类，项目是阶段性目标**：任务可以只有领域，没有项目；项目不能脱离领域存在。
- **硬约束不得降级为偏好**：最早开始时间、固定课程和保护时间不允许排程器突破。
- **识别结果不是事实**：OCR 只生成草稿，必须经过用户校对和最终确认。
- **本地优先**：课表图片默认只在本机处理，不调用云端识别服务。
- **迁移不猜测用户意图**：旧任务无法可靠推断领域时保留“未分类”，不自动塞入学业。
- **所有批量写入可追踪、可撤销**：课表导入以批次为单位记录。
- **可读性优先于玻璃效果**：输入框、高密度表格和正文保持高不透明度与足够对比度。

## 3. 方案选择

### 3.1 采用：增量扩展现有模型

在现有任务、项目、领域、固定日程和重复规则基础上增加必要字段与导入元数据。保持现有排程、统计和日历边界，只调整其数据来源与约束。

优点：

- 能复用现有仓库、服务、日历展开器与备份机制；
- 数据迁移可控；
- 不需要一次性重写任务和日历；
- 可以分阶段交付并持续测试。

### 3.2 不采用：为每个领域创建隐藏项目

这种方式改动较小，但会继续把“项目”当成领域的技术替身，污染项目列表，用户仍无法理解两者区别，统计也依赖隐藏数据。

### 3.3 暂不采用：重写为统一日程对象

统一任务、固定日程、保护时间和课程系列的长期模型更整洁，但会同时影响排程、统计、专注记录、备份和现有迁移，超出本轮需求的可控范围。

## 4. 核心概念与业务规则

### 4.1 领域

领域表示长期存在的责任或生活维度，例如学业、科研、竞赛、工作和生活。领域用于：

- 时间投入统计；
- 生活配额判断；
- 任务和项目筛选；
- 日历颜色与语义分类。

新安装默认建立以下领域：

| 排序 | 名称 | 默认生活领域 |
| --- | --- | --- |
| 1 | 学业 | 否 |
| 2 | 科研 | 否 |
| 3 | 竞赛 | 否 |
| 4 | 工作 | 否 |
| 5 | 生活 | 是 |

已有数据库升级时按规范化名称补齐缺失项，不覆盖用户已有领域，不制造同名重复项。

### 4.2 项目

项目是领域下具有阶段性结果、可以结束或归档的具体目标，例如：

- 学业 → 算法课程；
- 竞赛 → 数学建模校赛；
- 科研 → 图像分割实验；
- 工作 → 学生会招新；
- 生活 → 秋季摄影计划。

项目必须归属于一个领域。项目归档后不再出现在新任务的默认选择列表中，但历史任务仍保留关联。

### 4.3 任务归属

- 新建任务必须选择领域。
- 项目可选。
- 选择领域后，只显示该领域下未归档的项目。
- 修改领域且当前项目不属于新领域时，清空项目并提示原因。
- 选择项目时再次校验 `project.areaId == task.areaId`，避免界面绕过或旧数据造成不一致。
- 任务详情始终显示 `领域 / 项目`；没有项目时显示 `领域 / 无项目`。

旧任务迁移规则：

- 有项目：通过项目回填领域。
- 无项目：保持领域为空，并在界面显示“未分类”；首次编辑时要求选择领域。
- 不根据标题、标签或项目名称猜测领域。

### 4.4 最早开始时间

任务新增可选的 `availableFromUtc`：

- 未设置时，排程使用计划窗口开始时间与当前时间中的较晚者。
- 设置后，任何任务片段的开始时间不得早于它。
- 保存时若 `availableFromUtc >= dueAtUtc`，显示字段级错误并禁止保存。
- 最早开始时间是硬约束；“期望时段”仍是可被降级的软偏好。
- 时区转换只发生在界面与应用边界，数据库统一保存 UTC。

## 5. 数据模型设计

### 5.1 任务表

`tasks` 增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `area_id` | nullable text FK → areas | 迁移期间允许空；新建任务由服务层强制必填 |
| `available_from_utc` | nullable integer | 最早开始时间，UTC 微秒 |

选择 nullable `area_id` 是为了无损迁移旧的无项目任务。应用层对新建和编辑后的任务执行必填校验。

所有按领域工作的读取端改为优先使用 `tasks.area_id`。迁移期兼容策略为：若该列为空且存在项目，则回退到 `projects.area_id`，直至数据回填完成。生活任务判断不再要求任务必须有项目。

### 5.2 重复规则表

`recurrence_rules` 增加：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `interval_weeks` | integer | 1 | 每隔多少周重复，首版允许 1–52 |

单双周映射：

- 每周：`intervalWeeks = 1`；
- 单周：有效起点设为学期第一个符合条件的单周，`intervalWeeks = 2`；
- 双周：有效起点设为学期第一个符合条件的双周，`intervalWeeks = 2`。

展开器按 `validFromLocalDate` 所在周作为锚点计算周差。`validUntilLocalDate` 继续作为结束边界。对于“1–4周、8–16周”这类不连续范围，创建两个重复系列，并使用相同逻辑课程标识关联。

### 5.3 日历事件扩展

`calendar_events` 增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `project_id` | nullable text FK → projects | 课程或固定日程的可选项目归属 |
| `location` | text，默认空 | 教室或地点 |
| `notes` | text，默认空 | 教师、备注等 |
| `source_kind` | text，默认 `manual` | `manual`、`timetableImport` 等 |
| `import_batch_id` | nullable text FK → timetable_import_batches | 导入批次 |
| `logical_course_id` | nullable text | 关联同一课程的多个周次范围或上课时段 |

项目存在时必须与事件领域一致。导入课程一律设置 `locked = true`。

### 5.4 学期、节次模板与导入批次

新增以下表：

#### `academic_terms`

- `id`
- `name`
- `first_week_monday_local_date`
- `total_weeks`
- `time_zone_id`
- `created_at_utc`
- `updated_at_utc`

#### `period_templates`

- `id`
- `name`
- `is_default`
- `created_at_utc`
- `updated_at_utc`

#### `period_template_entries`

- `template_id`
- `period_number`
- `start_minute`
- `end_minute`

复合主键为 `(template_id, period_number)`。每节必须满足开始早于结束，节次编号必须唯一。允许用户保存多个学校或校区模板。

#### `timetable_import_batches`

- `id`
- `term_id`
- `source_image_hash`
- `source_file_name`
- `status`：`draft`、`committed`、`rolledBack`
- `created_event_count`
- `created_at_utc`
- `updated_at_utc`

默认只保存图片哈希和文件名，不把原始课表图片写入数据库或备份，避免隐私泄露和备份体积膨胀。导入向导关闭前，原图仅保存在内存或应用临时目录。

## 6. 详细新建任务界面

快速收集入口完全移除，所有入口统一进入详细新建页。表单使用已确认的结构：

1. **基本信息**：名称、预计时长、优先级。
2. **分类归属**：领域必选，项目可选。
3. **时间与拆分**：最早开始、截止时间、拆分方式、片段长度、期望时段。

表单初始值来自用户设置；所有默认值直接显示，用户可以修改后再创建。

领域使用清晰的可选择控件，项目字段位于领域之后。项目列表随领域过滤。字段下方用简短说明明确：

- 领域用于长期统计与生活配额；
- 项目用于管理一个可结束的具体目标。

“新建该领域项目”在当前表单内展开轻量区域，包含项目名称与只读/可确认的所属领域，保存后立即选中。完整项目管理页的新建项目则必须显式选择领域。

右侧预览展示归属、可安排窗口、所需容量与拆分规则。宽度不足时改为单栏，不制造横向滚动。

## 7. 课表导入向导

入口位于日历页“导入课表”，也可从设置中的“学期与节次模板”进入。采用用户确认的 A 方案：五步引导式导入。

### 7.1 第一步：上传图片

- 支持 PNG、JPG、JPEG。
- 支持拖放和文件选择。
- 展示原图，可裁剪与旋转后重新识别。
- 显示“仅在本机识别，图片不会上传”。
- OCR 不可用时提供“手动录入课程”入口，不阻断流程。

### 7.2 第二步：校对识别结果

本地 OCR 返回文字、边界框和置信度。课表解析器利用星期标题、节次刻度和单元格位置生成课程草稿。每个草稿包含：

- 课程名称；
- 教师；
- 教室；
- 星期；
- 起始节与结束节；
- 起始周与结束周；
- 每周、单周或双周；
- 领域，默认学业；
- 可选项目。

低置信度、缺少周次、无法定位节次或解析出异常范围的字段必须标记并要求检查。用户可以新增、删除、合并或拆分识别行。

总教学周数优先取识别结果中的最大结束周，但始终允许手动修改。

### 7.3 第三步：校准学期

同时提供：

- 参考日期与其周数，例如 `2026-10-05 = 第 5 周`；
- 第一周星期一，例如 `2026-09-07`。

修改任意一侧时即时换算另一侧。换算按本地日历日期计算，不通过 UTC 时长除法，避免夏令时问题。用户还需确认学期名称、总周数和时区。

### 7.4 第四步：设置节次

- 列出第 1 节至实际使用的最后一节；
- 每节分别设置开始和结束时间；
- 支持“每节 N 分钟、课间 M 分钟”的批量生成；
- 支持逐节修正并保存为个人模板；
- 开始时间不早于上一节结束时间；重叠或异常短节次显示警告。

连续课程按第一节开始至最后一节结束生成一个固定日程。例如第 1–2 节为 08:00–09:40，则生成 100 分钟事件，课间仍被课程占用。

### 7.5 第五步：预览并确认

预览把重复规则展开到具体日期，并展示：

- 将创建的课程数量、重复系列数量和具体发生次数；
- 每门课的日期、时间、周次、单双周、教师、教室和归属；
- 与现有固定日程的冲突；
- 完全重复和疑似更新项；
- 需要用户确认的异常字段。

用户可以排除单次发生、整个上课时段或整门课程。只有点击最终确认后才开启数据库事务。

## 8. 本地 OCR 架构

定义平台无关接口：

```text
TimetableOcrEngine
  recognize(image) -> OcrDocument(lines, words, boundingBoxes, confidence)

TimetableParser
  parse(document, imageGeometry) -> TimetableDraft
```

Windows 首版使用系统本地 OCR，通过 Flutter Windows 原生插件调用 Windows OCR API。运行前检查简体中文识别能力：

- 可用：执行本地识别；
- 缺少中文 OCR 语言能力：给出系统设置指引，同时允许手动录入；
- 识别失败：保留图片与已填内容，允许重试、换图或手动处理。

解析器与 OCR 引擎分离，后续可以增加打包模型或移动端实现，不影响向导和业务服务。首版不接入云端 OCR。

## 9. 排程规则

### 9.1 最早开始硬约束

排程问题构建时，每个任务的候选起点下界为：

```text
max(计划窗口开始, 当前时间向上取整到 5 分钟, task.availableFromUtc)
```

任务的每个片段都必须满足该下界。若剩余可用容量不足，任务进入不可完全安排结果，并明确说明是最早开始时间、截止时间、固定占用还是每日上限导致。

### 9.2 课程固定占用

导入课程展开为锁定的固定事件，占用对应时间范围。排程器不得移动、拆分、覆盖或压缩课程。课程变动通过修改重复系列或单次例外实现。

### 9.3 导入后的重新规划

导入提交后，如果新课程影响已确认计划：

- 默认生成调整预览，列出被移动、拆分或无法安排的任务；
- 开启“信任自动调整”时可直接应用可行调整；
- 即使开启自动调整，也不能静默突破硬约束；无解时仍需提示用户。

## 10. 冲突、重复与撤销

### 10.1 冲突检测

冲突检查在本地日期与时区规则下展开具体发生日期后执行，避免单双周造成误报。固定日程重叠时提供：

1. 保留现有日程并跳过冲突课程；
2. 保留课程并由用户编辑或删除现有日程；
3. 暂时保留冲突并标记“待处理”。

系统不自行覆盖现有固定日程。

### 10.2 重复导入

重复判断分两层：

- 批次层：同一图片哈希与相同学期视为疑似重复批次；
- 课程层：规范化课程名、星期、节次、周次范围和单双周完全相同视为完全重复。

完全重复默认跳过。时间规则相同但教师或教室变化时标记为“可能是信息更新”，允许更新原系列或新建。

### 10.3 整批撤销

每个导入事件保存 `importBatchId`。撤销整批导入时：

- 未被手动修改的事件直接删除；
- 已被手动修改或增加单次例外的事件列出并要求确认；
- 批次标记为 `rolledBack`，保留审计元数据；
- 撤销后触发可移动任务的重新规划预览。

提交与撤销均使用数据库事务。任一步失败时回滚整批写入，不留下半套课表。

## 11. 普通周期事项

固定日程编辑器增加：

- 不重复、每天、每周、每隔若干周；
- 指定星期；
- 起始日期与结束日期；
- 单周、双周快捷选项；
- 永不结束；
- 修改仅本次、本次及以后或整个系列。

“本次及以后”通过截断原规则并创建新规则实现；“仅本次”继续使用例外事件表达。删除也必须提供同样的作用范围。

## 12. 视觉与交互修正

### 12.1 深色文字

- 禁止在深色表面直接使用 `Colors.black*`。
- 标签、正文、辅助文字统一使用设计令牌 `textPrimary`、`textSecondary`、`textMuted`。
- 正文对比度至少 4.5:1。
- 新增主题与组件测试，防止硬编码黑色重新出现。

### 12.2 设置页间距

- 设置条目之间使用至少 12px 垂直间距；
- 分组之间使用 24px；
- 不依赖全局 `CardTheme.margin` 提供页面布局；
- 整行点击目标不小于 44px；
- 标题、说明和箭头保持统一对齐线。

### 12.3 表单与向导

- 标签始终位于输入框外，不只使用占位符；
- 字段级错误贴近对应字段；
- 所有步骤可返回，已经校对的数据不丢失；
- 键盘 Tab 顺序与视觉顺序一致；
- 小窗口自动切换单栏布局；
- 玻璃模式下输入区仍保持高不透明度。

## 13. 服务与模块边界

新增或调整以下应用服务：

- `TaskService`：校验领域、项目一致性和最早开始时间。
- `WorkspaceService`：补齐五个默认领域；新建项目必须提供领域。
- `CalendarService`：支持 `intervalWeeks`、课程元数据和系列修改范围。
- `AcademicTermService`：管理学期与周数换算。
- `PeriodTemplateService`：管理节次模板与校验。
- `TimetableImportService`：协调 OCR、解析、草稿、预览、事务提交和批次撤销。
- `TimetableConflictDetector`：展开日期后检测冲突与重复。
- `ScheduleProblemSource`：把 `availableFromUtc` 传入排程模型。

OCR 原始结构、课表草稿和最终日历对象使用不同类型，禁止把未经确认的识别结果直接交给仓库。

## 14. 数据迁移与兼容

数据库由当前 v3 升级到下一版本，实施计划中根据 Drift 迁移测试确定具体版本号与分步迁移。

迁移顺序：

1. 创建学期、节次模板和导入批次表；
2. 为任务、重复规则和日历事件增加列；
3. 通过项目连接回填旧任务的 `area_id`；
4. 为旧重复规则写入 `interval_weeks = 1`；
5. 将旧日历事件标记为 `source_kind = manual`；
6. 启动时幂等补齐缺失的默认领域；
7. 重新生成 Drift 代码并运行逐版本迁移测试。

备份清单继续使用数据库 schema version。新版本可以恢复旧备份并自动迁移；旧版本不得打开更高版本备份。

## 15. 错误处理与隐私

- 图片不可读：不进入 OCR，提示重新选择。
- OCR 不可用：提供中文语言能力说明与手动录入，不要求联网。
- OCR 中断：保留当前草稿，不写数据库。
- 学期换算不合法：阻止进入最终预览。
- 节次时间重叠或结束早于开始：字段级报错。
- 事务提交失败：完整回滚并保留可重试草稿。
- 图片默认不进入数据库、导出文件或备份。
- 日志只记录错误类别、步骤和批次 ID，不记录课表全文或原图路径。

## 16. 测试策略

### 16.1 单元测试

- 领域与项目一致性校验；

- 课程草稿规范化与重复键；

- v3 数据库升级；
- 有项目任务的领域回填；
- 无项目旧任务保持未分类；
- 新外键和事务回滚；
- 旧备份恢复后迁移；
- 导入和撤销的原子性。

### 16.3 组件测试

- 任务表单先领域后项目；
- 切换领域清空不兼容项目；
- 新建项目继承当前领域；
- 最早开始晚于截止时阻止保存；
- 五步向导可前进、返回并保存草稿；
- 低置信字段、冲突和重复项可操作；
- 深色模式没有黑色标签；
- 设置条目间距和返回路径。

### 16.4 集成测试

- 上传固定测试图片 → OCR 夹具 → 校对 → 学期校准 → 节次设置 → 预览 → 导入；
- 导入单双周课程后只在正确周次出现；
- 导入课程后任务自动规划不覆盖课程；

- 重复导入默认跳过；
- 整批撤销恢复导入前状态并触发重排预览。

## 17. 验收标准

1. 新任务可以直接选择五个默认领域之一，不需要先创建项目。
2. 项目选择位于领域之后，只显示当前领域项目。
3. 新建项目必须属于领域，任务内新建后自动选中。
4. 任务设置最早开始时间后，任何生成片段都不早于该时间。
5. 固定日程支持起止日期、每隔若干周及单双周。
6. 用户可以从日历进入五步课表导入向导。
7. 课表图片在本地识别；识别失败时可以手动录入。
8. 用户可以校对课程、周次、单双周、连续节次、教师和教室。
9. 当前周数与第一周星期一可以双向换算。
10. 每一节课的开始和结束时间可以修改并保存为模板。
11. 连续多节课程按首节开始至末节结束生成一条锁定日程。
12. 最终确认前能看到具体日期、冲突、重复项和创建数量。
13. 重复图片不会默认再次创建相同课程。
14. 整批导入可以撤销，已手动修改的事件不会静默删除。
15. 深色界面不再出现不可读的黑色标签，设置条目具有稳定间距。

## 18. 非目标

本轮不包含：

- 云端 OCR 或把课表上传到第三方；
- 教务系统账号登录或网页抓取；
- 课表与学校系统双向同步；
- 无需校对即可保证识别任意课表图片；
- 手机端课表导入；
- 对现有任务、日历和统计模型进行整体重写。
