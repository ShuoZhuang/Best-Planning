# 优计主义 Windows 离线单文件安装器设计

日期：2026-10-18

状态：设计已逐节确认，等待书面规格复核

目标版本：`1.10.0+47`

MSIX 版本：`1.10.0.0`

Git 标签：`v1.10.0`

## 1. 文档目的

本文定义优计主义 Windows 版本面向新用户的离线单文件安装器，以及它与现有应用内自更新系统、便携版和 GitHub Release 的边界。

最终目标是让新用户只下载并双击一个文件，在一次 Windows 管理员权限确认后完成：

```text
校验安装器内置载荷
→ 建立当前 MSIX 发布证书信任
→ 为发起安装的 Windows 用户安装或升级 MSIX
→ 验证真实安装结果
→ 清理临时文件
→ 启动优计主义
```

安装器必须包含完整 MSIX，断网也能完成首次安装。普通用户不需要操作 PowerShell、批处理、证书管理器或裸 MSIX 文件。

本文是架构规格，不授权直接修改安装器或应用代码。书面规格复核通过后，必须另行编写实施计划，再按计划开发和验证。

## 2. 与现有设计的关系

本文补充而不替代 `docs/superpowers/specs/2026-10-18-native-self-update-design.md`：

| 使用场景 | 负责组件 | 载荷 |
| --- | --- | --- |
| 从未安装过应用的新用户 | 本文定义的离线 Setup EXE | EXE 内嵌完整 MSIX 与公开证书 |
| 已安装用户的后续升级 | 既有应用内自更新系统 | 后台下载经过签名清单声明的 MSIX |
| 无管理员权限或临时使用 | 便携版 ZIP | 解压后的便携程序 |
| 管理员手动部署和故障恢复 | 原始 MSIX | Release 中的已签名 MSIX |

应用内自更新不下载 Setup EXE，不重复导入证书。Setup EXE 也不替代应用内更新状态机、后台下载、业务阻塞、健康确认和回退逻辑。

## 4. 用户目标与成功标准

### 4.1 新用户流程

1. 从项目官方 GitHub Release 下载 `BestPlanning_Setup_1.10.0_x64.exe`。
2. 双击运行。
3. 若 Windows SmartScreen 出现，用户核对下载来源后选择“更多信息 → 仍要运行”。
4. 同意一次 UAC 管理员权限请求；标准账户可以输入管理员凭据。
5. 安装器自动校验载荷、信任证书、安装 MSIX、清理临时文件并启动应用。
6. 用户不需要联网，也不需要手动选择证书或安装包。

### 4.2 已安装用户运行 Setup

- 未安装目标包：首次安装。
- 已安装较低版本：保留用户数据并执行 MSIX 原位升级。
- 已安装相同版本：显示“启动应用”或“重新安装”。
- 已安装更高版本：拒绝降级。
- 包身份或 Publisher 冲突：停止并给出明确错误，不自动替换。

### 4.3 成功标准

- 单个 EXE 在断网环境完成首次安装。
- 整个正常流程最多一次 UAC。
- 标准账户输入其他管理员凭据后，MSIX 仍安装给发起安装的原用户。
- 不调用 PowerShell、批处理或外部下载程序。
- 载荷未经全部验证时绝不导入证书或部署包。
- 升级不删除或重置任务、课程、保护时间、偏好与设置。
- 安装失败尽可能保持旧版本可运行。
- 临时目录和敏感中间文件得到可靠清理。
- Windows 10 和 Windows 11 真实部署矩阵通过。

## 5. 范围与非目标

### 5.1 本期范围

- Windows x64。
- 离线、单文件、原生 Setup EXE。
- 完整 MSIX 和公开证书内嵌。
- 一次 UAC 的双进程权限隔离。
- MSIX 哈希、签名、证书、身份、发布者、架构和版本验证。
- 首次安装、原位升级、相同版本修复和拒绝降级。
- 安装日志、错误分类和安全清理。
- 同时发布 Setup、Portable、MSIX、manifest 和 checksums。

### 5.2 非目标

- 修改、迁移或删除用户业务数据。
- 绕过或关闭 SmartScreen、Windows Defender、防火墙或系统安全策略。
- 把公开证书导入“受信任的根证书颁发机构”。
- 在线下载额外运行库或安装组件。
- ARM64、x86、macOS、Linux、Android 或 iOS 安装。
- 静默强制关闭正在运行的应用。
- 普通界面中的强制降级。
- 创建启动项、计划任务或遥测上传。
- 让便携版冒充具有 MSIX 身份的安装版。

每个正式版本固定发布：


Release 页面顺序为：

1. 普通新用户下载 Setup EXE。
2. 不安装或无管理员权限时下载 Portable ZIP。
3. 已安装用户通常无需手动下载，应用内更新自动准备 MSIX。
4. 裸 MSIX、manifest 和 checksums 面向管理员、测试人员和诊断场景。

旧式“证书 + MSIX + PowerShell 安装脚本”压缩包不再作为普通用户推荐入口。若为迁移兼容保留一个版本，必须明确标为旧式安装方式并在后续版本移除。

## 7. 总体架构

### 7.1 单文件、双进程

安装器在磁盘上只有一个 EXE，运行时采用权限分离：

```text
普通权限主进程
├─ 展示界面
├─ 创建安全安装会话
├─ 校验内嵌 MSIX、证书与元数据
├─ 发起一次 UAC
├─ 以发起安装的用户身份部署 MSIX
├─ 验证安装结果
└─ 启动应用
          │
          └─ 提权辅助进程
              ├─ 独立重复验证会话和载荷
              ├─ 写入 LocalMachine\TrustedPeople
              └─ 返回结构化结果后退出
```

不能让整个安装器全程提权。标准用户在 UAC 中输入另一个管理员账户时，全程提权会把 per-user MSIX 安装给管理员账户，违反用户预期。

### 7.2 内嵌内容

Setup EXE 的只读资源包含：

- 最终已签名 MSIX；
- MSIX 的公开签名证书，不含私钥；
- 载荷元数据；
- 包身份、Publisher、目标架构和目标版本；
- MSIX 精确字节长度与 SHA-256；
- 证书 SHA-256 指纹与公钥摘要；
- 安装器版本；
- 用于安装后查询的应用标识信息。

这些值必须由同一次发布构建自动生成，禁止人工在多个文件中复制。

### 7.3 组件职责

1. `EmbeddedPayloadReader`：读取内嵌 MSIX、证书和元数据。
2. `SecureExtractionSession`：创建、保护和清理随机临时会话。
3. `PackageVerifier`：校验文件、签名、证书和包身份。
4. `ElevationBroker`：建立一次 UAC 与受保护进程间通信。
5. `CertificateTrustManager`：只管理固定公开证书的 `TrustedPeople` 信任。
6. `PackageDeploymentManager`：以原用户身份调用 Windows 包部署接口。
7. `ApplicationLauncher`：从实际登记结果解析并启动真实 AUMID。
8. `InstallerStateMachine`：限制合法状态转换和取消点。
9. `InstallerLogger`：记录可审计、无业务数据的诊断信息。
10. `InstallerUi`：只展示状态和用户可理解的处理建议。

界面不得绕过控制器直接调用证书写入或软件包部署接口。

## 8. 安全信任链

### 8.1 固定顺序

```text
启动普通权限主进程
→ 创建受保护随机会话
→ 读取内嵌元数据
→ 释放 MSIX 与公开证书
→ 校验字节长度与 SHA-256
→ 解析 MSIX 包清单
→ 校验包身份、Publisher、架构和版本
→ 验证 MSIX 数字签名的密码学完整性
→ 确认实际签名者等于内嵌固定证书
→ 启动提权辅助进程
→ 提权进程独立重复上述关键校验
→ 导入固定证书到 LocalMachine\TrustedPeople
→ 普通进程重新执行 Windows 信任验证
→ 部署前再次确认载荷未被替换
→ 以原用户身份安装或升级 MSIX
→ 查询系统中的真实登记结果
→ 清理临时会话
→ 启动应用
```

任何一步失败都不得越过到后续步骤。

### 8.2 首次安装时的签名验证

首次安装时证书尚不受系统信任。因此必须区分：

1. MSIX 签名是否在密码学意义上完整；
2. 实际签名者是否正是安装器固定的公开证书；
3. 该证书是否已经受到本机信任。

安装器先完成前两项，再导入该证书，随后重新执行 Windows 正常信任验证。不得为了让验证通过而先盲目信任 MSIX 自带或外部选择的证书。

### 8.3 固定身份

当前稳定边界为：

- Package Identity Name：`ShuoZhuang.PersonalPlanner`
- Publisher：`CN=Shuo Zhuang, O=Personal User, C=CN`
- Architecture：`x64`
- 目标 MSIX Version：`1.10.0.0`

Package Family Name 和 AUMID 应从最终包清单及实际系统登记结果生成和验证，不能依赖容易漂移的展示名称或硬编码磁盘路径。

### 8.4 临时载荷保护

- 使用密码学安全随机名称创建专用会话目录。
- 目录和文件使用限制性 ACL。
- 拒绝符号链接、连接点和其他重解析点。
- 文件采用排他创建，不覆盖既有路径。
- 不使用固定 `%TEMP%\BestPlanning` 目录。
- 验证后到部署前再次核对大小、SHA-256、签名和文件身份。
- 会话令牌只能使用一次。
- 提权进程不接受任意用户文件路径。
- 安装结束或失败后清理本次会话；清理失败必须写入日志。

### 8.5 进程间通信

- 使用带 ACL 的本地命名管道或等价 Windows 安全 IPC。
- 会话包含高熵一次性 nonce。
- 提权进程验证父会话身份、nonce、协议版本和载荷摘要。
- 提权进程从正在运行的同一个 Setup EXE 的只读资源中重新读取证书和固定元数据，不依赖原用户配置文件或临时目录中的证书文件。
- 即使 UAC 使用的是另一个管理员账户，提权进程也不得切换为给该管理员部署 MSIX；它只负责机器级证书信任，包部署仍由原始普通权限进程完成。
- 协议只允许“验证并信任固定证书”这一组有限命令。
- 不允许传递任意命令行、脚本、注册表路径或证书存储区。
- 返回结构化状态和错误码，不返回可执行文本。

### 8.6 证书规则

- 只导入安装器内嵌的公开证书。
- 目标固定为 `LocalMachine\TrustedPeople`。
- 不导入私钥，不写入 Root。
- 已存在相同指纹证书时复用。
- 相同主题但指纹或公钥不同不视为相同证书。
- 不删除系统中其他同名证书。
- 安装失败时只有满足安全回收条件才移除本次新增证书。
- 普通卸载应用时不自动删除证书。

### 8.7 Setup EXE 自身

- Setup EXE 使用正式发布证书签名。
- 先完成资源嵌入，再签名 EXE；签名后禁止修改文件。
- Release 同时公布 Setup EXE 的 SHA-256。
- 当前自签名证书可能触发 SmartScreen，安装器不得修改系统策略绕过。
- MSIX 与 EXE 均使用可信时间戳，并由发布门禁验证时间戳存在。

## 9. 安装状态机

### 9.1 状态

```text
INITIALIZING
→ PREFLIGHT_CHECK
→ EXTRACTING
→ VERIFYING_PAYLOAD
→ REQUESTING_ELEVATION
→ TRUSTING_CERTIFICATE
→ REVERIFYING_PAYLOAD
→ DEPLOYING_PACKAGE
→ VERIFYING_INSTALLATION
→ CLEANING_UP
→ COMPLETED
```

终止状态：

- `CANCELLED`
- `BLOCKED`
- `FAILED_BEFORE_CHANGE`
- `FAILED_AFTER_CERTIFICATE`
- `FAILED_DURING_DEPLOYMENT`
- `FAILED_AFTER_DEPLOYMENT`

每次转换必须记录时间、来源状态、目标状态和规范化结果。非法跳转不得执行系统写入。

### 9.2 安装前检查

- Windows 版本满足最低要求。
- 系统与包均为 x64。
- 内嵌资源完整。
- 临时空间充足。
- Windows 包部署服务可用。
- 当前用户与原始交互会话可确定。
- 是否已有同一安装器实例。
- 目标包是否已安装、版本为何、是否正在运行。
- 是否存在阻止部署的待重启状态。

第二个安装器实例只能激活已有窗口后退出，不得并发部署。

### 9.3 应用正在运行

安装器不默认强制结束应用。界面提示用户保存并退出，然后提供“重新检测”和“取消安装”。确认应用及相关后台进程退出后才继续。

### 9.4 首次安装

- 验证所有固定身份和签名。
- 建立证书信任。
- 为原始用户登记软件包。
- 重新查询实际版本、身份、状态和 AUMID。
- 成功后启动应用。

自动启动失败不撤销成功安装，结果为“应用已安装，但自动启动失败”。

### 9.5 原位升级

- 不先卸载旧版。
- 不使用清除数据、重置应用或删除缓存参数。
- Windows 部署失败后重新查询旧版是否保留。
- 不能仅根据一次 API 异常推断包完全没有改变。
- 升级后业务数据由应用级验收测试逐项确认。

### 9.6 相同版本

显示“当前版本已经安装”，提供：

- 启动应用；
- 重新安装；
- 退出。

重新安装仍执行完整验证，并使用 Windows 支持的重新登记或修复方式，不能先卸载。

### 9.7 拒绝降级和身份冲突

- 已安装版本高于目标版本时中止，不提供普通界面的强制降级。
- Identity 相同但 Publisher 不同、展示名称相同但 Identity 不同、签名者不一致或架构不匹配时中止。
- “载荷完整性失败”和“已安装不兼容包”必须显示不同错误。

### 9.8 取消边界

允许取消：

- 安装前检查；
- 等待关闭应用；
- 正式系统写入开始前。

不能立即中断：

- 正在写入证书；
- Windows 正在部署包；
- 正在查询和确认最终系统状态。

关键阶段收到关闭请求时，界面显示“正在完成关键步骤”，等待调用返回后再安全退出。

## 10. 失败恢复

### 10.1 阶段矩阵

| 失败阶段 | 可能改变系统 | 处理 |
| --- | --- | --- |
| 启动检查 | 否 | 说明条件并退出 |
| 释放资源 | 否 | 删除临时会话 |
| 文件或签名校验 | 否 | 删除临时会话，绝不导入证书 |
| UAC 被拒绝 | 否 | 返回取消或权限不足 |
| 导入证书 | 可能 | 记录证书此前是否存在 |
| 部署前复验 | 可能仅新增证书 | 满足安全条件时回收证书 |
| MSIX 部署 | 可能 | 查询系统实际登记状态 |
| 安装后验证 | 是 | 保留成功包并报告异常 |
| 自动启动 | 是 | 不回滚安装，提示手动启动 |

### 10.2 证书回收条件

只有同时满足以下条件才允许删除本次导入的证书：

- 安装前不存在该证书；
- 目标 MSIX 没有成功安装；
- 系统中不存在依赖该证书的受支持 Best Planning 包；
- 没有其他已知受支持包使用该证书；
- 删除动作本身经过记录。

无法证明安全时保留证书，不能误删旧版本仍依赖的信任。

### 10.3 最终状态

- `Installed`：目标版本成功安装。
- `PreviousVersionPreserved`：升级失败，旧版仍正常。
- `InstalledButLaunchFailed`：安装成功，仅启动失败。
- `Indeterminate`：系统状态暂不明确，需要重启后复查。
- `NotInstalled`：目标包没有安装。

### 10.4 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 安装或升级成功 |
| `10` | 用户取消 |
| `20` | 环境不支持 |
| `21` | 应用仍在运行 |
| `30` | 安装载荷校验失败 |
| `31` | 证书处理失败 |
| `40` | 部署失败，旧版已保留 |
| `41` | 部署失败且目标包未安装 |
| `42` | 最终状态不明确 |
| `50` | 安装成功但启动失败 |
| `60` | 检测到更高版本，拒绝降级 |
| `70` | 包身份或 Publisher 冲突 |
| `99` | 未分类内部错误 |

## 11. 用户界面

### 11.1 准备页

显示：

- 应用名称与目标版本；
- 发布者；
- 首次安装、升级或重新安装；
- “安装后启动优计主义”，默认开启；
- “安装”和“取消”。

升级时显示旧版本和目标版本，并明确用户数据将被保留。

### 11.2 等待关闭应用

显示保存和退出提示，仅提供：

- 重新检测；
- 取消安装。

不提供默认强制结束按钮。

### 11.3 进度页

使用稳定的非技术阶段文案：

- 正在检查安装包；
- 正在配置安装环境；
- 正在安装优计主义；
- 正在验证安装结果；
- 正在完成。

无法获得可靠进度时使用不确定进度动画，不伪造百分比。

### 11.4 完成页

显示实际安装版本，提供“启动优计主义”和“完成”。自动启动已经成功时只需显示完成状态。

### 11.5 错误页

每个错误包含：

- 简明标题；
- 用户能理解的原因；
- 当前系统状态；
- 推荐处理方式；
- 稳定错误编号；
- 适用的重试、复制信息、打开日志或退出操作。

不得只显示 HRESULT、原始异常或调用栈。

## 12. 日志与隐私

日志可记录：

- Setup 和目标版本；
- Windows 版本与架构；
- 状态转换；
- 载荷校验结果；
- 部署错误码；
- 安装前后包版本；
- 证书是复用、新增还是安全回收；
- 最终安装状态。

日志不得记录：

- 任务、课程、日程或偏好内容；
- 业务数据库内容；
- GitHub 凭据或令牌；
- 私钥或证书密码；
- 与诊断无关的用户文件清单。

日志不自动上传。界面可以提供“打开日志位置”和“复制错误信息”。

## 13. 应用内自动更新边界

### 13.1 正常职责

应用内更新继续执行：

1. 后台读取经过签名验证的稳定通道清单；
2. 判断 MSIX 版本是否更高；
3. 自动下载并验证 MSIX；
4. 在左下角显示更新状态和入口；
5. 用户点击后进入安全更新流程；
6. 关闭主程序后由原生更新助手部署；
7. 启动新版、等待健康确认并在必要时恢复。

### 13.2 无弹窗规则

以下情况不主动弹出模态窗口：

- 发现更新；
- 开始或完成后台下载；
- 断网；
- GitHub 限流；
- 暂时无法检查；
- 用户尚未点击更新入口。

网络失败和限流不得显示为“已经是最新版本”。

### 13.3 Manifest

`update-manifest.json` 只描述应用内更新使用的 MSIX，不把 Setup EXE 当作更新载荷。至少包含：

- schema version；
- release version 与 build number；
- MSIX version；
- stable channel；
- x64 architecture；
- Package Identity 与 Publisher；
- MSIX asset name、size 和 SHA-256；
- 最低 Windows build；
- 是否强制更新。

实际协议继续服从现有原生自更新设计中的签名信封、来源限制和严格解析规则。

## 14. 构建和发布流水线

### 14.1 顺序

1. 校验工作区、版本与发布配置。
2. 构建 Flutter Windows 应用。
3. 生成 MSIX。
4. 使用正式证书签署 MSIX。
5. 验证签名、时间戳和包清单。
6. 生成内嵌载荷元数据。
7. 将最终 MSIX、公开证书和元数据嵌入 Setup。
8. 编译 Setup EXE。
9. 签署 Setup EXE。
10. 验证 EXE 签名和时间戳。
11. 生成 Portable ZIP。
12. 生成应用内更新 manifest。
13. 计算所有最终文件 SHA-256。
14. 执行版本与文件名一致性门禁。
15. 执行 Setup 自检和自动化测试。
16. 全部门禁通过后才允许上传 Release。

### 14.2 私钥与证书

- 私钥和密码不得进入 Git。
- 日志不得输出密码。
- 正式与测试证书分离。
- 正式 Setup 拒绝测试证书签署的 MSIX。
- 构建前检查证书用途、有效期和时间戳能力。
- 证书轮换必须另行设计，不能直接破坏旧客户端更新链。

### 14.3 版本一致性门禁

自动核对：

- `pubspec.yaml` 应用版本；
- MSIX 四段版本；
- Setup 显示版本与文件版本资源；
- Git Tag 和 Release 标题；
- manifest 版本；
- Release 附件文件名；
- checksums 中的文件名和哈希；
- MSIX 清单中的 Identity Version；
- 应用运行时报告版本。

任一不一致必须使发布失败，不能只警告。

## 16. 测试策略

### 16.1 单元测试

- 版本比较及拒绝降级。
- Identity、Publisher 和架构比较。
- 文件长度与 SHA-256。
- 证书指纹、公钥和主题比较。
- 状态机合法转换。
- 错误码映射。
- 证书安全回收判定。
- manifest 和 Release 文件名一致性。
- GitHub 限流、断网与无更新状态区分。

### 16.2 组件测试

- 内嵌资源正确提取。
- 修改 MSIX 任意一个字节后校验失败。
- 替换证书、签名者或同名不同指纹证书后失败。
- Identity、Publisher、架构或版本不符时失败。
- 临时路径含重解析点时拒绝。
- 验证后替换载荷时拒绝。
- 无效会话 nonce 被提权进程拒绝。
- 提权进程拒绝任意路径和未知命令。
- 普通流程不调用 PowerShell。
- 日志中不出现业务数据和秘密。

### 16.3 真实部署矩阵

| 环境 | 账户 | 必测场景 |
| --- | --- | --- |
| Windows 10 x64 最新受支持版本 | 管理员 | 首次安装、升级、卸载重装 |
| Windows 10 x64 最新受支持版本 | 标准账户 | 输入管理员凭据后安装给原用户 |
| Windows 11 x64 当前稳定版本 | 管理员 | 首次安装、升级、相同版本修复 |
| Windows 11 x64 当前稳定版本 | 标准账户 | 权限隔离及原用户安装 |
| Windows 11 x64 当前稳定版本 | 管理员 | 应用内更新、失败恢复和回退 |

没有实体测试机时使用 VirtualBox 或 VMware 的干净虚拟机与快照。当前开发机上的成功安装只能算冒烟测试。

### 16.4 数据保留用例

升级前建立：

- 普通、已排程和已完成任务；
- 周期目标；
- 课程及修改后的课程时间；
- 早餐、午餐、晚餐和睡眠保护时间；
- 自定义保护时间；
- 学习偏好；
- 特殊日和延长日；
- 通知与自动更新设置。

升级后逐项确认数据、标题、时间和标识符保持，排程未被安装过程擅自重算，关闭重开后结果仍一致。

### 16.5 故障注入

至少覆盖：

- 内嵌 MSIX 缺失或损坏；
- 证书或 Publisher 被替换；
- manifest 与包版本不一致；
- UAC 被拒绝；
- 证书写入失败；
- 应用未关闭；
- Windows 部署失败；
- 部署期间虚拟机被强制中止；
- AUMID 查询失败；
- 自动启动失败；
- 磁盘空间不足；
- 临时目录不可写；
- GitHub 限流、下载中断和下载后损坏。

每个故障必须记录用户提示、系统改变、旧版状态、证书状态、是否可重试、日志和退出码。

## 17. 发布阻断条件

出现任意一项不得发布：

- 未完成全部校验就能进入证书导入或部署。
- 安装器信任非固定证书。
- 标准账户的包被安装到提供凭据的管理员账户。
- 升级删除、重置或损坏用户数据。
- 失败后旧版本无法启动且没有明确恢复结论。
- 可以从普通界面静默降级。
- Setup、MSIX、manifest、Tag 或 checksums 版本不一致。
- GitHub 请求失败被显示为“已是最新版本”。
- Setup 首次安装依赖网络、PowerShell 或外部脚本。
- EXE 或 MSIX 签名、时间戳无效。
- 正式产物包含测试证书。
- Windows 10 或 Windows 11 必测环境未执行。
- 关键验收只有模拟结果，没有真实部署证据。

## 18. 完成定义

只有以下条件全部满足，才能宣布离线单文件安装器完成：

- 原生 Setup 代码和共享验证组件完成。
- 单元测试与组件测试全部通过。
- 最终 MSIX、公开证书和元数据正确内嵌。
- 断网首次安装通过。
- 管理员和标准账户场景均通过。
- Windows 10、Windows 11 虚拟机真实部署通过。
- 旧版本原位升级并保留全部业务数据。
- 相同版本修复通过，高版本降级被拒绝。
- 故障恢复与证书回收经过真实验证。
- Setup、Portable、MSIX、manifest 和 checksums 同时发布。
- 应用内更新仍只使用 MSIX。
- Release 下载说明与 SmartScreen 说明完成。
- 验收记录包含环境、版本、结果、证据和日志位置。
- 没有未说明的 `PARTIAL` 或 `NOT RUN` 项。

缺少真实 Windows 部署演练时，只能标记为“代码完成，发布验收未完成”，不得宣布正式完成。

## 19. 已确认决策

1. 使用原生 C++ 单文件引导安装器，不使用 PowerShell 作为正常安装路径。
2. Setup 内含完整 MSIX，断网可安装。
3. 同时保留 Setup 安装版与 Portable 便携版。
4. 接受自签名证书阶段可能出现 SmartScreen，绝不通过降低系统安全性绕过。
5. 使用一次 UAC、双进程权限隔离。
6. 公开证书只写入 `LocalMachine\TrustedPeople`，不写入 Root。
7. 安装后保留证书，以支持同 Publisher 的后续 MSIX 更新。
8. Setup 支持首次安装、升级和同版本修复，但拒绝普通降级。
9. Setup 成功后默认启动应用。
10. 应用内更新仍采用后台下载、左下角入口和用户点击后安装，不弹出发现更新窗口。
11. 架构更新目标版本为 `1.10.0+47` / MSIX `1.10.0.0` / Tag `v1.10.0`。

## 20. 后续流程

本文通过书面复核后：

1. 使用计划编写流程生成逐文件、逐测试、逐提交的实施计划。
2. 计划必须先处理共享验证库和权限分离，再接 Setup 界面和发布流水线。
3. 实施前确认 `feature/native-implementation` 与目标主分支的基线关系。
4. 不在脏的主工作区直接开发安装器。
5. 实施完成后执行自动化测试、代码复核和真实虚拟机验收。
