# M7 补充规格：图表在四档材质下的可读性

> 补上 `docs/testing/m7-acceptance.md` §3 里唯一未通过的那一条（路线图 §11 第 5 条）：
> **"图表在四档材质下通过对比度检查，并提供可读的明细替代"**。
> **不抬版本、不单独发布**；**不带入 M8**（§14）。

## 1. 先量，再定口径（实测数据）

现有图表把**白色标签直接画在饼图切片上**（`chart_view.dart` 的 `PieChartSectionData.titleStyle`）。
按 WCAG 相对亮度实测，同一张饼的八种颜色里**只有三种**能到 4.5:1：

| 颜色 | 白色标签对比度 | |
| --- | --- | --- |
| `#3567D4` | 5.20:1 | ✅ |
| `#8B5CC7` | 4.72:1 | ✅ |
| `#9A6B4B` | 4.59:1 | ✅ |
| `#4B8A9A` | 3.89:1 | ❌ |
| `#D6576B` | 3.86:1 | ❌ |
| `#7A8B3C` | 3.76:1 | ❌ |
| `#1F9D7A` | 3.41:1 | ❌ |
| `#E39035` | 2.53:1 | ❌ |

「领域占比」用的是**领域调色板**，更糟（白字在 `#f2b35d` 上只有 **1.85:1**）。

**换成深色也不成立**：逐色试过——`dark #142131` 或 `black` 取较优者，`#3567D4`（4.04）与
`#8B5CC7`（4.45）**仍然不达标**。

**结论：饼图切片上的文字没有一种固定前景色能满足四档材质。**
这不是靠"换个颜色"能修的，**必须改变信息的呈现方式**。

## 2. 口径（本规格定下来的判据）

| 图形元素 | 判据 | 理由 |
| --- | --- | --- |
| **文字**（标签、数值、轴名） | WCAG 正文阈值 **≥ 4.5:1**，对**它实际所在的背景** | 与 M2 的正文判据一致，用 Flutter 的 `textContrastGuideline` |
| **图形本身**（饼图区、柱、折线） | **≥ 3:1** 对它所处的表面 | 与 WCAG 的"图形对象／界面组件"阈值一致（非文本 3:1）。它**不是**文字，不该套 4.5 |
| **不能只靠颜色区分** | 每个数据点必须有一处**文字**给出它的**名称与数值** | 色盲用户与黑白打印都要能读懂 |

**实现方向（由口径推出，不是为了省事）**：

- **把饼图切片上的文字拿掉**，改在图表**下方**放一行**图例**（颜色块 + 名称 + 数值）。
  文字回到正常表面上，4.5:1 就可达；
- 图例同时满足"不只靠颜色区分"——名称与数值都在文字里；
- 柱状／条形／折线本来就把标签与数值画在图表外（轴与旁列），只需确认它们达标。

## 3. 强制测试

`test/features/analytics/chart_contrast_test.dart`（新文件，**四档材质各跑一遍**）：

| 要求 | 测试 |
| --- | --- |
| 四档材质下整张统计卡片通过 `textContrastGuideline` | 对四档 `PlannerMaterialMode` 分别 `expectLater(tester, meetsGuideline(textContrastGuideline))` |
| **饼图切片上不再有文字** | 渲染饼图后断言图表区域内**没有**切片标题文字（`find.text(label)` 至少在图表控件的子树上不存在），文字只出现在图例里 |
| **图例给出名称与数值** | 每个数据点都能在页面上找到"名称"与它的"分钟数"两处文字 |
| 图形对表面 ≥ 3:1 | 用与 M2 同一套相对亮度算法，对每个 `ChartDatum.color` 与其所在表面求比值 |
| 空数据与单点数据有专门状态 | 值为 0 的项不画；全为 0 时显示 `emptyLabel`；只有一个数据点时不崩 |
| **先红后绿** | 本文件在修复前必须失败（切片上的白字会触发对比度违规） |

## 5. 明确不做

- 不换图表库、不改 `ChartKind` 的四种类型、不改图表类型选择的持久化。
- 不改统计口径、不改各卡片的脚注文案。
- 不为了达标而**去掉**任何信息：切片上少的那几个字要在图例里补齐。
- 不做 M8 引导。
