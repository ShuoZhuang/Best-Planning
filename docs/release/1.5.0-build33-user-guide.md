## 1. 已完成待办重复——**上一版没修对，这版换了修法**

你说"还是没有改善"，是对的。我去把你的数据库摊开看，发现**我上一版的规则本身就是错的**：

| 你的实际数据 | 后果 |
| --- | --- |
| `算法作业` 今天在当前版是 **10:00**、在旧版是 **07:30** | 两个版本的块并起来 → 今天出现**两次** |
| `大物预习课`（已完成）在旧版是 **50+90 分钟**、在新版是 **90+50 分钟** | 并起来 → 昨天出现**三四次** |

上一版只按"任务 + 开始时刻"去重，只消得掉**时间完全相同**的那一条；`算法作业` 那条被挪了 2.5 小时、
`大物预习课` 那两条时长都不一样，所以照旧重复。

**这版的规则**：**一个本地日只由一版计划决定**，不再把各版本求并集。

1. 那一天**当前版本有安排** → 只用当前版本（它是最新声明）。今天与未来都走这一支，所以"把任务改到
   别的时间"不会再同时显示新旧两个位置；
2. 那一天**当前版本没有安排、且这一天已经完整过去** → 用"**当天结束时在用的那一版**"（即
   `createdAt ≤ 当天结束` 里最新的那一版）——这就是"当时排了什么"的还原，也是你要的
   "已完成的计划不要被后来的调整改掉"；
3. 其余留空：今天／未来若当前版本本来就没排，不该从历史里捞回来。

依据是：**一版计划是对那段时间的完整声明**。跨版本求并集在语义上就是错的。

验收图 `acceptance-1.5.0-build33-today-no-duplicate.png`：今日里 `算法作业` **只出现一次**
（10:00–10:40），带已完成对勾。

## 2. 选择统计范围下面那块日历没有透光了

也是我上一版改坏的：本应用的 `ColorScheme.surface` 用的是**玻璃半透明色**（如 `0xcc142131`），
所以选择器的日历区原本能透出下面；我为了修按钮对比度，把它的底色写成了**不透明**的调色板色，
透光就没了。

现在改成：**只改对比度、不改透光**——底色从当前玻璃模式取色。测试里直接钉住 `alpha < 1`，
以后谁再把它写成实心色都会红。
