# 优计主义 1.8.1 更新

这一版重做了**排程内核**：任务不再只盯着"切碎硬塞"，而是先算清"每一天到底还剩多少可用时间"，再把工作量摊到最合适的几天上。

**你大概率会看到的变化：**

- 周末的空闲终于会被用上了。以前它会沿用周一的上限、把工作量继续堆在工作日
- 一天里"已经锁定的安排"会真正占掉额度。以前锁定 300 分钟、上限 360 的一天还能再排 360 分钟
- 一个任务被切成几段时，会分散到多天，而不是全挤在第一天

---

## 逐日规则：周末不再复制周一

- **每天的每日上限、排程粒度、休息间隔、生活配额各按当天自己的规则生效**。以前整周都取窗口首日那份，于是"周末上限更高"这类设置**整周不起作用**
- 时段偏好与精力区间本来就分工作日／周末；现在其余的日期敏感字段也一并对齐

## 单一容量账本：一天到底还剩多少，只有一个答案

- 新增统一的容量账本：**可用空档、许可容量、已用额度、剩余额度**都从它来
- 账本把**锁定块算进"已用"**。修复前锁定 300 分钟、每日上限 360 的一天，仍会被允许再排进 360 分钟
- 放置、诊断、局部改进三处读**同一份口径**，不会各说一套

## 跨日分配：先定"摊到哪几天"，再决定"放在几点"

- 先把任务的总分钟按方案级目标摊到 K 个日期，K 由算术约束决定（`K × 最小片段 ≤ 目标`）
- 目标是**字典序**比较：先看硬约束，再看新增缺口、优先级分布、单日负载率、节奏偏差、稳定性——**不是**一个加权分数
- 修复了一个实测缺陷：180 分钟曾被摊到 **8 天、每天 20–25 分钟**，而最小片段是 30 分钟——**每天都不够放一块**，于是一个块都排不出来。现在 K 受 `目标 ÷ 片段` 限制

## 稳定性：不再为了很小的改善就重排

- 局部改进新增**方案级闸门**：某一块换到"更讨喜"的位置时，还会再比较**整份方案**是否更好；否则不动
- 这挡住了实测出现过的一种坏形状：局部精力分更高，却把工作日负载从 70% 推到 100%、周末仍是 20%
- 局部改进现在也**守跨日预算**，不会把分配好的额度在收尾阶段挪乱

## 你已有的计划会被原地保留

- **未锁定的既有计划块会带着原身份进入重排**。修好之前引擎会给所有块重新起名，于是"尽量少改动"那一步**实际是空操作**——它找不到任何"原来的位置"
- 现在移动一块会保留它的身份，预览能如实报成**「移动」**而不是"删除＋新增"
- 锁定块、固定日程、保护时间的身份与语义**一字未改**

## 解释文案更诚实

- 高精力任务被排到普通时段时，以前理由是**「优先级较高」**——那与事实无关，你也没法据此做什么
- 现在会如实说**「偏离精力偏好」**：你因此知道可以调整精力区间，或者把占住那个时段的课挪开
- 旧计划里的旧解释码仍然能被正确显示，不会退化成兜底文案

---

## 这次修掉的具体缺陷

| 症状 | 原因 |
| --- | --- |
| 生成本身抛错、整次失败 | 取"当天粒度"时把 **UTC 瞬间当成本地日期**；窗口起点在本地零点时查到窗口外的日子 |
| 锁定 300 分钟的一天还能再排 360 分钟 | 引擎算"已用额度"时**跳过锁定块** |
| 均匀任务被摊成每天 20–25 分钟、一个块都排不出 | 参与日数 K 没有受 `最小片段` 约束 |
| 分配好的额度在收尾阶段被挪乱 | 局部改进没有**守跨日预算** |
| 无截止的连续任务抢走有截止任务唯一的窗口 | 分配顺序把"连续"排在"截止"之前 |
| 连续任务明明放得下却报缺口 | 只尝试排名第一的那一天，放不下就放弃 |
| "尽量少改动"不生效 | 既有块的 id 与确认计划不同族，参照永远匹配不上 |

## 下载与校验

**免安装版（推荐先试这个）**

1. 下载并解压 `PersonalPlanner-1.8.1-build45-windows-x64-20261017.zip`
2. 双击 `personal_planner.exe`
3. 首次运行会在 exe 旁生成 `user-data\`（数据库与诊断日志）——那是**你自己的数据**，删掉就等于清空应用

**安装版（进开始菜单、支持原位升级）**

1. 解压整个文件夹（**不要**只复制单个文件）
2. 双击 `安装.cmd`——它会信任证书并安装，需要一次 UAC 确认
3. 已装 `1.8.0.x` 的用户可直接覆盖升级，数据不需要迁移

**校验**

`SHA-256.txt` 在包内。重点看两项：

```text
MSIX : 6ADCDF7AEBF6E4592716330E88D9D47A349E0AF9E016F8D4B2B595FBA35565CF
ZIP  : E3C9457544D5195CBF03C20B1381726D9FAE5CE93AB68ADBE1F8EB7B183FFC31
```

Dart 代码本体是包内 `data\app.so`（`D8AB3AC2…`）。**别拿 `personal_planner.exe` 的哈希判断内容**——它只是启动器，本次与上一版同值。

**数据库**

schema 未变，无需迁移。从 `1.8.0.x` 升级不会改动你的数据。
