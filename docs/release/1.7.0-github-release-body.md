# 智能日程 Personal Planner `1.7.0`

> 一个发布批次里的全部改进：统计复盘重做、日程导航修正、按周固定时长的周期目标、
> 默认开启的更新检查，以及一处会让真实可用时间被误判为"排不下"的排程缺陷修复。

**产物**：`PersonalPlanner-1.7.0-build40-windows-x64-20261008.zip`（`1.7.0+40` / MSIX `1.7.0.2`）

---

## 这一版做了什么

### 1. 统计复盘重做

原先是一条长列表，要一路滑下去才知道有什么。现在分成**四个页签**，每一页回答一个不同的问题：

| 页签 | 回答的问题 |
| --- | --- |
| 时间分配 | 时间分给了谁 |
| 计划质量 | 计划合不合理 |
| 休息与作息 | 有没有给自己留休息 |
| 调整记录 | 计划是怎么被改出来的 |

顶部先给**四项摘要**（计划总时长／任务完成率／保护时间达成率／最需处理的问题），每一项都能点开
**来源明细**，看到这个数字是由哪些块、哪些任务算出来的。

修掉的口径问题：

- 横轴不再出现重复的"上周"或重复日期；周范围最多 7 个标签，长范围按规则抽样。
- 主图不再显示裸分钟——`1195` 现在写成 `19 小时 55 分钟`。
- "今天"在午夜后重新计算，不会继续显示昨天的范围。
- 空白时间不再叫"休息"，改叫"可用空闲／未安排"。
- 所有比例都写出分子与分母。

### 2. 不同事项去到各自的详情

今日页上点一件事，现在会按类型去正确的地方：**任务** → 任务详情；**固定日程**（课表、会议）→
当天视图；**保护时间**（午餐、睡眠）→ 保护规则。此前三者都往任务详情走，于是课表和午餐会
打开一个空的任务页。

### 3. 按周完成固定时长：周期目标

适合"每周英语 180 分钟"这类目标。新建入口在 **任务页 →「新建」→「周期目标」**
（新建入口现在叫「新建」而不是"新建任务"，因为它还能建周期目标和固定日程）。

可以设置目标时长、片段范围、领域与项目、**节奏**（均匀分布／截止日加权／尽早完成／仅指定星期）、
允许的星期、以及**是否结转**未完成的分钟（默认**不结转**）。

周期的**周界是本地时间周一 00:00 到下周一 00:00**。每周会生成一个普通任务实例交给既有排程器，
因此它和普通任务一起参与排程、一起出现在日历上。周期详情页显示本周进度、本段分钟、历史周次，
以及每种操作的影响范围（只改这一周／改整个系列）。

**任务页现在有「周期目标」分组**，点进去就能管理：**编辑、暂停、跳过本周、停止以后生成、删除**。

「停止以后生成」是**归档**——以后都不做了，但已生成的周期与记录原样保留，统计里仍看得到历史。
「删除」则是**清掉**模板、全部周期与那些周期对应的任务（连带专注记录），历史周次一起消失，
不可撤销。两者刻意分开：把归档当删除用会让你以为数据没了而其实还在统计里。

### 4. 修复：排不下的任务既不排、也说不清原因

这是这一版最实的一处修复。

**问题**：一个 15 分钟的任务配上默认片段 30–90 分钟时，会**一个片段都产不出来**，于是它
**同时出现在"新增"和"未安排"里**，而原因只写一句笼统的"可用时间不足"。

**现在**：

- 最终余量短于最小片段时**仍然可以安排**；
- 未安排的原因是**结构化的**，例如"这件事需要一次做完：需要 30 分钟，可用 20 分钟"、
  "已经达到这一天能安排的上限"、"还没到这件事可以开始的时间"；
- 预览里显示**任务名称**，不再是 UUID。

**另一处**：当天滚动规划的起点原先取**本地午夜**，而引擎判断"现在"用的正是这个起点，于是下午
生成计划可能把块排进**当天已经过去**的时段。现在起点是"现在"向上取整到 5 分钟网格，
终点不变。

### 5. 课表课程结束后留出移动时间

**新功能**：上完课要离开教室，不可能直接接续。现在**课表导入的课程结束后默认留 10 分钟**
不安排计划。

- **只对课表导入的课生效**，自己建的会议不受影响；
- **只加在结束后**，不加在开始前（课与课之间的空隙由课表本身提供，两侧都加会叠加成 20 分钟）；
- 位置：**设置 → 规划规则 →「专注与任务片段」→「课后缓冲（分钟，仅课表）」**，
  填 `0` 即关闭。

### 6. 今日页可以「延后本次」

当前计划块可以一键**延后 10 分钟**——临时接了个电话、还没走回宿舍，这类"这一块现在做不了，
往后挪一点"此前只能整块拖动或干脆不做。延后是**一次性**的位移，不会把块永久钉住。

### 7. 更新检查（默认开启）

设置 → 检查更新。**只检查，不下载、不安装**；有更新时由你自己去 GitHub 下载。

- 自动检查默认开启，24 小时内不会重复请求；手动「立即检查」总能立即发起。
- **离线或 GitHub 限流不影响使用**：自动检查失败不打扰你，手动检查给一句短消息。
- 有更新时显示一条可关闭的提示；**关掉之后同一个版本不再出现，但下一个新版本仍会提醒你**。
- 「跳过这个版本」之后不再提示它。
- 除更新检查这一次 HTTPS 请求外，程序不联网。

### 8. 一致性与体验收口

- 状态消息统一：短暂提示可**撤销**（完成／跳过本次／调低本周目标／放宽期望时段），
  长期提示可**关闭**且读屏会播报。
- 空状态不再只解释现状，会给出**下一步**（例如统计页没有计划时给「去生成计划」）。
- 150%／200% 缩放、窄窗、键盘与读屏的主流程都有自动化证据。

## 数据与兼容性

- **数据库从 schema v6 升到 v8**（`1.6.2` 及更早的用户）。
- 升级前会自动生成一份快照，放在数据库旁边的 `pre-upgrade-backups` 目录里。
- **升级不删数据**：升级前后任务、日程、计划、设置逐表行数不变，外键检查干净。
- v8 迁移还会**修好一类历史脏数据**：片段范围自相矛盾的任务（最短片段大于最长片段，或片段
  上下限超过任务总时长）。**实测在你的真实备份上，10 条任务里有 8 条属于这种情况。**
  它**只修片段两列**——剩余时长、截止时间、标题、备注一律不动。
- 卸载不会删除用户数据库。

## 安装

下载名称含 `windows-x64` 的完整 ZIP，完整解压后双击 `安装.cmd`。它会先把签名证书装进
「受信任人」，再用 `Add-AppxPackage` 安装／**原位升级**同目录的 `.msix`。

- 本包是**自签名**的，所以必须先信任证书，否则双击 MSIX 会被 Windows 拒绝。
- **安装不需要卸载旧版**：`1.7.0.0` 严格高于 `1.6.2.0`，可以原位升级，用户数据不受影响。
- 升级前请**退出正在运行的旧版**（托盘常驻会让进程活着，导致安装报 `0x80073D02`）。
- 校验值见包内 `SHA-256.txt`。

## 这一版不包含

- 周期目标的"完成前二次确认"与"近期计划冻结"（计划放在 `1.7.1`）。
- 周期目标卡片上的"本段 x 分钟"——今日与日历卡片只显示本周累计（详情页有本段分钟）。

## 已知限制

排程在**极高块密度**下会变慢：引擎的重叠检查对每个候选扫一遍全部已排块。真实使用量级
（一周窗口、每天几十块）实测 1.6 秒；把数千块压进一周会到几十秒。这不影响日常使用，
但已记入构建台账与验收表的 §5.4。
