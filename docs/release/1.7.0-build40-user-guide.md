# 智能日程 Personal Planner `1.7.0` 使用教程

> **本文件对应候选 `1.7.0+38` / MSIX `1.7.0.0`（2026-10-08）。** 产物已构建，**尚未正式发布**。
> 之前那份教程是 [`1.6.2-build37-user-guide.md`](1.6.2-build37-user-guide.md)，**界面操作部分仍然适用**，
> 本文件只讲 `1.7.0` 改了什么、以及哪些地方与上一版不同。两处冲突时以本文件为准。
>
> 更新说明（叙述版）见 [`1.7.0-release-notes.md`](1.7.0-release-notes.md)。

## 安装

下载名称含 `windows-x64` 的完整 ZIP，完整解压后双击 `安装.cmd`。它会先把签名证书装进
「受信任人」，再用 `Add-AppxPackage` 安装／**原位升级**同目录的 `.msix`。

- 本包是**自签名**的，所以必须先信任证书，否则双击 MSIX 会被 Windows 拒绝。
- **安装不需要卸载旧版**：`1.7.0.0` 严格高于 `1.6.2.0`，可以原位升级，用户数据不受影响。
- 升级前请**退出正在运行的旧版**（托盘常驻会让进程活着，导致安装报 `0x80073D02`）。

## 这一版改了什么

### 1. 统计页重做了

原先是一条长列表，要一路滑下去才知道有什么。现在分成**四个页签**：

| 页签 | 回答的问题 |
| --- | --- |
| 时间分配 | 时间分给了谁 |
| 计划质量 | 计划合不合理 |
| 休息与作息 | 有没有给自己留休息 |
| 调整记录 | 计划是怎么被改出来的 |

顶部是四项摘要（计划总时长／任务完成率／保护时间达成率／最需处理的问题）。每一项都可以点开
**来源明细**，看到这个数字是由哪些块、哪些任务算出来的。

下面多了**周期目标**摘要卡（见第 3 条）。卡上明确写着"**不计入上面的计划时长**"——这是刻意的：
周期目标统计的是目标进度，而上面的计划时长统计的是计划块，两者是不同的事实，加在一起就没有意义了。

**没有计划时**，摘要卡会直接给一个「去生成计划」按钮；**没设保护时间时**给「去设置保护时间」。

### 2. 不同事项去到各自的详情

今日页上点一件事，现在会按类型去到正确的地方：

- **任务** → 任务详情
- **固定日程**（课表、会议） → 当天视图
- **保护时间**（午餐、睡眠） → 保护规则

此前三者都往任务详情走，于是课表和午餐会打开一个空的任务页。

### 3. 周期目标：按周完成固定时长

适合"每周英语 180 分钟"这类目标。新建入口在 **任务页 →「新建」→「周期目标」**（新建入口现在
叫「新建」而不是"新建任务"，因为它还能建周期目标和固定日程）。

可以设置：

- **目标时长**与**片段范围**（每段最短／最长）
- **领域**与项目（项目按领域过滤）
- **节奏**：均匀分布（摊到每天）／截止日加权／尽早完成／仅指定星期
- **允许的星期**（只有选「仅指定星期」才出现）
- **是否结转**未完成的分钟（默认**不结转**）

周期的**周界是本地时间周一 00:00 到下周一 00:00**。每周会生成一个普通任务实例交给既有排程器，
因此它和普通任务一起参与排程、一起出现在日历上。

在周期详情页可以看到：本周进度、本段分钟、历史周次，以及**每种操作的影响范围**（只改这一周／
改整个系列）。

**排不下时会说清原因。** 这是这一版修得最实的一件事：此前一个 15 分钟的任务配上默认片段
30–90 分钟，会一个片段都产不出来，于是它**同时出现在"新增"和"未安排"里**，而且原因只写一句
"可用时间不足"。现在：

- 最终余量短于最小片段时**仍然可以安排**；
- 未安排的原因是**结构化的**，例如"这件事需要一次做完：需要 30 分钟，可用 20 分钟"或
  "已经达到这一天能安排的上限"；
- 预览里显示**任务名称**，不再是 UUID。

缺口卡片给四个处理动作：调低本周目标／放宽期望时段／临时放宽每日上限／允许本周不完全安排。
其中前两个现在**可以撤销**（气泡上有"撤销"）。

### 4. 更新检查（默认开启）

设置 → 检查更新。**只检查，不下载、不安装**；有更新时由你自己去 GitHub 下载。

- 自动检查默认开启，24 小时内不会重复请求。
- 手动「立即检查」总能立即发起。
- **离线或 GitHub 限流不影响使用**：自动检查失败不打扰你，手动检查给一句短消息。
- 有更新时会显示一条可关闭的提示；**关掉之后同一个版本不再出现，但下一个新版本仍会提醒你**。
- 「跳过这个版本」之后不再提示它。
- 数据不出本机：除更新检查这一次 HTTPS 请求外，程序不联网。

### 5. 一致性与体验

- 状态消息统一走同一套：短暂提示可**撤销**，长期提示可**关闭**且不会被读屏漏掉。
- 空状态不再只解释现状，会给**下一步**该做什么。

## 数据与兼容性

- **数据库会从 schema v6 升到 v8**（`1.6.2` 及更早的用户）。升级前会自动生成一份快照，
  放在数据库旁边的 `pre-upgrade-backups` 目录里。
- **升级不删数据**：升级前后任务、日程、计划、设置逐表行数不变，外键检查干净。
- 这次 v8 迁移还会**修好一类历史脏数据**：片段范围自相矛盾的任务（最短片段大于最长片段，
  或片段上下限超过任务总时长）。实测在真实备份上，10 条任务里有 8 条属于这种情况。
  **它只修片段两列**——剩余时长、截止时间、标题、备注一律不动。
- 卸载不会删除用户数据库。

## 这一版不包含

- 周期目标的"完成前二次确认"与"近期计划冻结"（计划放在 `1.7.1`）。
- 周期目标卡片上的"本段 x 分钟"——今日与日历卡片只显示本周累计（详情页有本段分钟）。

## 已知限制

- 排程在**极高块密度**下会变慢：引擎的重叠检查对每个候选扫一遍全部已排块。真实使用量级
  （一周窗口、每天几十块）实测 1.6 秒；把数千块压进一周会到几十秒。见构建台账与
  `docs/testing/v1.7-acceptance.md` 的 §5.4。
